# Narrow no-op publication contract
The API publishes authoritative AutoBlock snapshots every5s even while disabled. AutoBlockSet currently performs a full ACL reconciliation under the same transaction gate on every snapshot; the watcher already avoids inactive clean empty work. New narrow rule: AFTER existing owner/entry validation, transaction lock and closed check, acknowledge an empty publication without cache rewrite/ACL scheduling ONLY when protection is disabled, the retained cache is empty, it is not dirty AND a nonempty recorded fingerprint proves a prior successful runtime reconciliation. Initial/unknown state, loaded dirty caches, retained entries, enabled protection and all nonempty publications still persist/reconcile with existing behavior. Existing native base ACL authority, failed cleanup/retry, startup loss replay, expiry and active readback remain unchanged. No lock bypass or deadline increase.
