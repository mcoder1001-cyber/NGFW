# BFD and redistribution

Open Routing → BFD to edit standalone VPP sessions and read VPP/FRR live state. Set an existing interface, its assigned local IP and peer IP; TX/RX intervals are microseconds, default300000, detection multiplier defaults3. Save the candidate, inspect its diff and commit. Rollback removes scheduler-owned sessions and restores prior FRR profiles. CLI uses the corresponding `/api/v1/config/routing/bfd` pointer and ordinary commit/rollback commands.

Authentication accepts keyed-SHA1 or meticulous keyed-SHA1, a wire key ID0–255 and `key/<name>` referring to an encrypted secret1–20bytes. Existing sealed secret delivery pins the revision's material and never returns it through session state. Rotate with a new reference name and then move sessions to it: VPP refuses changing a key in use. The generated numeric key ID stays within this agent's assigned range; collisions are rejected.

For OSPF+BFD over linux-cp, enable BFD on the OSPF interface and optionally select a named profile from `routing.bfd.profiles`. FRR profile intervals must be whole milliseconds expressed in microseconds. IS-IS profile attachments work likewise; BGP uses its own BFD attachment. Protocols create dynamic FRR peers, so the BFD section does not invent standalone FRR peers with unknown remote IPs.

VPP claims BFD UDP ports for an entire address family and hop type while any session exists, including admin-down sessions. Therefore VPP standalone and FRR protocol BFD cannot coexist for the same AF/hop type on the box; conflicting protocol `bfd` fields fail validation. The shared-lab FRR linux-cp proof needs a manager window with no VPP BFD sessions, or isolated netns↔netns peers. Standalone multihop uses durable endpoint ownership and requires the existing globals owner. Non-owner agents reject it before activation. VPP global multihop enable is one-way until VPP restart: removing or rolling back sessions releases the owned sessions and endpoint claims, while that capability remains enabled. Retrieve and events match exact endpoint tuples and preserve their logical interface.

Open Redistribution matrix to view source→target edges and route-map references from committed state. Counts come from scoped per-protocol FRR route summaries, never a full-RIB dump; `?` means unavailable. Click an editable target cell to edit the target protocol's redistribution form; BGP links to its existing editor. OSPFv3/RIPng rows are read-only. A static route must set `viaFrr: true` before FRR can advertise it into OSPF; then enable static redistribution and select a route map that filters the desired prefixes. The VPP static-route builder excludes FRR-owned routes.

Routing policy reuses the existing prefix-list/route-map editors. Move up swaps sequence numbers, which changes FRR evaluation order; array order alone would not. Where-used links include redistribution in BGP/OSPF/IS-IS/RIP. BGP's existing editor includes its peer/network references.

Live endpoints: `GET /api/v1/state/routing/bfd/sessions` and `GET /api/v1/state/routing/redistribution`. BFD changes stream on `bfd-redistribution.events`. Session state never reports synthetic Up. Last-flap timestamps are omitted when the engine does not expose reliable observations. Policy hit-counter endpoint is omitted because no stable scoped FRR counter reader was verified.
