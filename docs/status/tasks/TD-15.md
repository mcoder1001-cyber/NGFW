## What

**ARCH-04 — response DTOs single-sourced via `z.output`.**
- `apps/api/src/common/responses.ts`: `ApiOut(schema, description?)` is now the one decorator for a 2xx JSON
  response; it always emits the `output` side of the Zod DTO. Plus `Out<S>` (= `z.output<S>`), `Wire<T>` (Date →
  string, as JSON sends it) and `SameKeys<T, S>`, a compile-time guard that fails `tsc` when an internal type and its
  documented DTO have different top-level keys (the error names the key: `{ undocumented: "secretVersions" }`).
- All 33 `@ApiOkResponse({ schema: openapi(X, 'output') })` in the 7 controllers replaced by `@ApiOut(X)` (response-
  schema hunks only). The generated OpenAPI document is byte-identical except the drift fix below.
- **Drift fixed:** `GET /config/revisions/:rev` now documents `secretVersions` (`RevisionOut`), which the handler
  returns. Guards added in `config.controller.ts`: `RevisionMeta ↔ RevisionMetaOut`, `Revision ↔ RevisionOut`,
  `SyncStatus ↔ SyncOut`.

**ARCH-11 — `userHashes`/`secretVersions` in `ConfigTx`, pool timeout.**
- `ConfigTx` gains `userHashes()` and `secretVersions(refs)`; `PgConfigTx` runs them on the transaction's own
  connection (shared `readUserHashes`/`readSecretVersions` helpers, also used by `PgConfigRepo`).
- The in-transaction callers now use `tx.*`: `commit.service.ts` promote (`secretVersions`, `userHashes`) and
  `datastore.service.ts` edit (stale-lock takeover check, secret-change marking). Before, each took a SECOND pool
  client while holding one — 10 concurrent edits with `VRX_DB_POOL_MAX=10` deadlocked the pool.
- `db.ts`: `connectionTimeoutMillis: POOL_CONNECT_TIMEOUT_MS` (10 s; pg's default 0 waits forever).
- `MemoryConfigRepo` implements the two new tx reads against the transaction's snapshot.

**ARCH-05 — secret refs from the schema.**
- `documents.ts`: `secretRefMembers()` derives the ref member names from `RootConfig`'s JSON Schema (every property
  whose schema, through `$ref`/`anyOf`/`oneOf`/`allOf`/`items`, carries `x-vrx-ui.widget: 'secret-ref'`, i.e. is a
  `secretRefOf(…)` field). `secretRefs()` uses that set instead of the `/Refs?$/` key regex. Pin: a secret-ref schema
  reachable only as a record value or bare array item (no member name) throws on first use, so every unit test that
  touches `secretRefs` fails.
- Derived set today (probe run): `authRef, certificateRef, keyRef, passwordRef, pinRef, presharedKeyRef, privRef,
  privateKeyRef, secretRef` — identical to the old regex's matches, so no behaviour change today.
