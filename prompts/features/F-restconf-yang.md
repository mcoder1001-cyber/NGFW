# Task: F-restconf-yang — RESTCONF compatibility layer + YANG generated from the schema   (prepend 00-CONTEXT.md)

## Goal
TNSR API parity at the protocol level (WBS D8.8 in `plan/wbs.csv`): YANG 1.1 modules **generated** from the Zod root schema (one module
per root key) and a RESTCONF (RFC 8040) layer that maps data-resource GET/PUT/PATCH/DELETE onto the existing candidate/commit engine.
Reference: TNSR "RESTCONF API" (TNSR is clixon-based, YANG-first); here the Zod schema stays the single source (00-CONTEXT rule 5).

## Inputs to read first
- `packages/schema/src/{index,gen}.ts` — root keys (`system … management`), JSON Schema / OpenAPI generation; `withUi` meta; `secret: true`
  meta + `redactSecrets`/`secretPointers` (D-046, D-070) — secrets are write-only in YANG too
- `apps/api/src/config/{config.controller,path}.ts` and `apps/api/src/commit/commit.service.ts` (P06, merged — read them on main) — the generic
  pointer routes, candidate lock, validate/commit/confirm/rollback; `apps/api/src/common/problem.ts` (problem+json) — RESTCONF errors map to
  `ietf-restconf` error bodies instead; `apps/api/src/app.ts` `configureApp` (content-type parsers; an 8 MiB body limit) and
  `apps/api/src/auth/route-guard.test.ts` (every route is guarded unless it is on the reviewed PUBLIC list)
- D-045/D-053: keyed collections are **records** (maps) → YANG `list` with the record key as `key` leaf; arrays with `itemKey` meta →
  `list` keyed by those fields; plain arrays → `leaf-list` or keyless `list` (config false not allowed → document)
- RFC 8040 (RESTCONF), RFC 7950 (YANG 1.1), RFC 8525 (YANG library), RFC 6243 (with-defaults)

## Contract changes
None expected — this task consumes the schema. If a Zod construct cannot be expressed, put the YANG hint in a side table inside
`packages/yang` keyed by JSON pointer (no edit of the 13 domain files, which other features are extending in parallel). Only if that is
impossible: an additive `.meta({ yang: … })` as a `contract(schema): …` commit on YOUR task branch (workers never create `contract/` branches),
questions file, continue.

## Scope — build exactly this
Files you own: `packages/yang/**` (new workspace package: generator + generated `.yang` + golden tests), `apps/api/src/features/restconf-yang/**`,
`apps/web/src/domains/system/restconf-yang/**` (only a "download YANG" link card), `apps/web/src/locales/*/restconf-yang.json`,
`docs/user/system/restconf-yang.md`, `test/topology/restconf-yang/**`. Shared files: one-line appends only under your anchor (the envelope
lists them: `app.module.ts`, router/nav/i18n, the route-guard PUBLIC list if a route is public, the `yang-data+json` parser if it cannot be
registered from your own module); `pnpm-lock.yaml` is regenerated by the manager at merge.
1. **Generator** (`packages/yang`): Zod → YANG: strictObject → container, record → list keyed `name`, enums → enumeration, int ranges →
   range, regex → pattern (XSD-compatible or dropped with a comment), `.optional()`/defaults → `default`, `description` from `withUi`
   titles/help, secret leaves → `nacm:default-deny-all` + never readable; `pyang --strict` (or `yanglint`) validates every module in a test if
   the tool is installed — **neither is installed on this host** (no host package installs; a worktree-local venv only if PyPI is reachable),
   else a documented manual gate. Deterministic output, checked in, CI fails on drift. The generator runs as part of `pnpm gen` (a `gen`
   script in packages/yang), so every later schema change regenerates the modules with the other generated files; the manager adds the
   output directory to `GEN_PATHS` in tools/ci.sh (manager-owned — ask in the questions file, do not edit it).
2. **RESTCONF** (`apps/api/src/features/restconf-yang`): `/.well-known/host-meta`, `/restconf`, `/restconf/data[/…]` GET (running or
   candidate via `?content`/datastore param — decide and document), PUT/PATCH (merge, `application/yang-data+json`), DELETE, `/restconf/
   operations/vrx:commit|rollback|confirm` mapped to the commit engine; `/restconf/data/ietf-yang-library:yang-library`; RFC 8040 JSON
   encoding (module-qualified names) ↔ the document's JSON pointer; same auth/RBAC/audit as `/api/v1`.
3. **Tests**: golden YANG per root key; round-trip: RESTCONF PUT of a sample document == `/api/v1/config` GET; secret leaves never
   returned; error bodies per RFC 8040 §7.
4. **Docs**: `docs/user/system/restconf-yang.md` — curl examples (GET interfaces, PATCH a VRF, commit), module list, known deviations.

## Acceptance (paste the evidence)
- [ ] `yanglint`/`pyang` validates all generated modules (pasted) — or the manual-gate note if neither tool exists
- [ ] `curl -H 'Accept: application/yang-data+json' …/restconf/data/vrx-interfaces:interfaces` returns the running config (pasted)
- [ ] RESTCONF PATCH + `operations/vrx:commit` → change visible in `/api/v1/config` and a new revision; rollback via RESTCONF works
- [ ] Invalid value → RESTCONF error body with `error-path` (the pointer equivalent) and HTTP 400
- [ ] API restart → RESTCONF routes served again, no state lost; `tools/ci.sh --base main` green in your worktree

## Out of scope (do not build)
NETCONF (SSH subsystem, XML encoding, `<edit-config>`/locks) — not feasible in FAST MODE, record as a have-not; RESTCONF notifications/event
streams (SSE), YANG for operational state (`config false`) beyond yang-library, gNMI, Terraform/Ansible/SDK (F-sdk-terraform-ansible),
CLI (P13), changes to the commit engine semantics (P06).

## Open questions to surface, not to decide silently
YANG module namespace/prefix (`urn:vrx:…`) and organisation name; whether RESTCONF writes go to candidate+auto-commit (TNSR-like) or require
an explicit `vrx:commit` operation (default: explicit, like `/api/v1`); whether `/restconf/**` appears in the OpenAPI document (default: no —
`@ApiExcludeController()`, so the generated api-client, the CLI operations table and the SDK do not grow generic RESTCONF operations);
whether `/.well-known/host-meta` is public (default: guarded like everything else). The dev stack (`tools/app`, port 8080) proxies only
`/api` — test RESTCONF against your slot API port; the product nginx (P10) must also route `/restconf` and `/.well-known/host-meta`.
