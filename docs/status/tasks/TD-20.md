## What changed

1. **`test/topology/interfaces/interfaces_test.go`** — the `trace add af-packet-input` + `show trace max 5000` block is gone.
   The same path (af-packet-input on the lan side → ip4-lookup → ip4-rewrite → wan output, and back) is proven without a trace:
   - FIB: `ip_route_lookup` (table 0, exact) of `<wanIP>/32` and `<lanIP>/32` — exactly one path, via the wan / lan
     sw_if_index, next hop = the host; `show ip fib table 0 <ip>/32` must be that /32 and rewrite via that interface.
   - ip4-lookup: the /32's load-balance `to:[packets:bytes]` counter rises by **exactly** n packets and n × IP length
     (run-unique size 1000 + pid%300) — every packet ip4-lookup forwards through that entry is counted.
   - interfaces: rx of `host-<p>l0` and tx of `host-<p>w0` (requests), rx of `host-<p>w0` and tx of `host-<p>l0` (replies)
     each rise by exactly n echo-sized frames; at most 4 extra frames of ≤ 200 bytes (ARP of the quiet rig) are admitted,
     and since 4×200 < the smallest echo frame (1042 B), the byte count admits n and only n echo frames (`echoFrames`).
   - the ping itself must report n sent / n received.
   Necessary hunks outside the "trace block only" ownership (flagged for the merger): `helpers_test.go` — the unit test of the
   removed `ourTrace` parser replaced by unit tests of `echoFrames` (9 cases incl. one-missing / one-extra / ARP-padded),
   `pingCounts` and the counter regex; `vpp_test.go` — `counterRe` also reads `rx/tx bytes`, header comment.
2. **`tools/ci.sh`** — new step `do_trace_ban` in `check`, `quick` and `full` (after `do_forbidden`): `git grep --untracked`
   for trace commands as argv lists (Go `vppctl(t, "show", "trace")`, TS/Python arrays), command strings (`"show trace"`,
   `"vppctl -s … trace add"`), shell `vppctl … show trace|trace add|clear trace` and the tracedump API
   (`TraceDump`/`trace_dump`/`TraceCapturePackets`/… and `binapi/trace` imports). Exempt: docs/, prompts/, wbs/, plan/,
   `*.md`, comment-only lines, apps/agent/binapi. No escape hatch. Message names D-128 and the alternatives.
   The step clears `CUR_LOG` (a failure no longer prints the previous step's gitleaks log) and escapes backslashes
   (`fail` prints with `%b`).
3. **`docs/lab/shared-host-rules.md` §11** — "Packet trace is banned on the shared VPP (D-128)": reason, evidence path,
   alternatives (interface counters, FIB entry + to-counter, tcpdump in the rig netns; `pcap trace` is global, no substitute).
