## Proposed selection: conditional design approval

Explicit private certificate selection can preserve the **installed trust invariant**: installed primaries must exactly equal independently authorized full fingerprint set, with existing validity checks. It changes the handling of a raw upstream superset, so it must be a named reviewed preprocessing policy, not silent weakening of verify_repo_key or its original duplicate/unmatched tests. The current source remains fail-closed until implementation satisfies these constraints and independent review/CI passes. No blanket approval of source code not yet written.

1. Preserve bounded regular nonsymlink input validation and reject secret packets/identities across the ENTIRE raw bundle before import. Do not discard unknown material first and thereby hide secret/malformed input. GPG parsing failures abort.
2. Pins remain explicit authorized full primary fingerprints, validated before network/side effects. FRR may use independently published pins only through a logged trust-source decision; no automatic pin derivation from download and no fourth pin added. Node trust gate unchanged.
3. Fresh private0700 transient GPG home, no user configuration/global keyring/keyserver/WKD retrieval. All argv fixed flags plus strictly validated full fingerprints. Require successful import; never proceed from a partially imported keyring after nonzero status.
4. Export complete selected public certificates (not export-minimal/export-clean/drop-signature filters), merging repeated instances to retain revocations/latest self-signatures instead of choosing the first copy. Preserve negative validity and missing-identity failure. Do not silently omit a revoked/malformed selected certificate to make validation pass.
5. Run unchanged verify_repo_key against the selected bounded regular output in a fresh private validation context; exact set equality still required. Both FRR and Node must validate before any installed keyring or APT mutation. Unknown fourth primary may exist transiently only and must not be exported/installed.
6. Tests must keep all existing raw-validator rejection cases unchanged and add REAL GPG certificate fixtures: harmless duplicate deduplication, extra unpinned primary exclusion, missing authorized primary, revoked/expired authorized primary, conflicting duplicate containing revocation, malformed/secret raw material, failed import/export and no global side effects. Prove exported installed identity set exactly equals authorized set. Hosted quick still mandatory; no lab PASS substituted.

Private proof-of-concept (no source changes): GPG import processed public bundle; export explicitly named three full fingerprints; selected output passed unchanged validator exit0 and produced private output. **Import itself returned2 due sandbox gpg-agent startup/socket error**, although public keys were partially imported. Therefore this is limited selection/parser evidence, NOT successful end-to-end import workflow acceptance. A production implementation MUST refuse that nonzero import. No agent failure may be swallowed merely to make this experiment pass.

Alternative with less preprocessing: upstream corrected bundle or individually published canonical public certificates, still validated against explicit pins; current raw exact-set validator can remain the whole pipeline. Waiting for upstream is not logically required if the constrained selection policy is implemented safely, but is preferable to weakening failures or silently trusting extra keys.

GnuPG primary reference: https://www.gnupg.org/documentation/manuals/gnupg/GPG-Input-and-Output.html documents export-clean/minimal signature removal, supporting requirement to avoid those filters. No proof of anti-rollback freshness beyond fetched certificate material is claimed; an omitted upstream revocation cannot be recovered from a stale download by selection.
