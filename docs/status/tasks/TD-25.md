# TD-25 — ifsanitize: stop the classify-pool hole ratchet

Branch `task/TD-25`, worktree `/root/ngfw-wt/TD-25`, base `main` @ 4f472cc7. Slot 1 for the host proof only.
Evidence logs (not committed): `/root/ngfw-wt/logs/TD-25-evidence/`.

## Root cause: the manager's reading is confirmed, with one correction to the growth rate

- **VPP facts**, from `/root/vpp/src` v26.06, read only:
  - `vppinfra/pool.h`: `_pool_get` pops `free_indices[n_free-1]` (LIFO), `_pool_put_index` appends, and the vector never
    shrinks.
  - `vnet_classify_new_table` uses `pool_get_aligned_zero(cm->tables)`.
- **The old algorithm** (`sanitize.go`, FreshRun = 8), on every create-phase run:
  1. resurrected **every** free index;
  2. then popped 8 fresh indices "to prove the free list empty";
  3. then deleted all of them in reverse order.
- **Why it ratchets:** the 8 fresh indices become new free-list entries at the tail. That is permanent growth of **8 per
  create** (not 2 × FreshRun: the second FreshRun was only slack in the cap). The delete phase never resurrected, so it did
  not grow the pool. Every later create had to pop the whole, larger free list. After a few dozen creates the list exceeded
  `PlaceholderCap` (64), and every create failed closed (ErrCapped).
- **Reproduced first on the model**, then on the host (below). The base failing test is pasted in "Verification" 1.

## What changed (`apps/agent/internal/vpp/ifsanitize/`)

Sanitize now reads bindings back exactly, and resurrects **on demand only**:

| kind | before | now |
|---|---|---|
| ip4/ip6 ip classify, l2 in/out classify | blind reset | blind reset (unchanged; a reset names no table) |
| input ACL | `classify_table_by_interface` | unchanged; a freed table is resurrected only for its own index |
| policer classify (ip4/ip6/l2), flow classify (ip4/ip6) | unbind probe over every table and placeholder | **exact readback**: `policer_classify_dump` / `flow_classify_dump` with `sw_if_index` **0**, see (1) |
| output ACL (ip4/ip6/l2) | unbind probe over every table and placeholder | **no readback in VPP** → detected per slot with the run's one probe placeholder P, see (2); only a slot proven bound is probed, through the existing tables and then freed indices |
| ADL, vxlan bypass, SPD, L3-mode reset | — | unchanged |

1. **The sw_if_index-0 dump.** The handler walks `vec_len(&vec[sw_if_index])` (`classify_api.c:472-507`, `:755-790`). With
   `~0` it returns nothing, and any other index reads out of bounds (why D-063 made policer write-only). With **0** the pointer
   *is* the vector, so the dump returns every binding of every index, deleted ones included (like `show classify policer`).
   Sanitize keeps only its own rows and never sends another index; the model fails a test that does. The host test proves the
   behaviour on a reused index other than 0.
2. **The output-ACL probe.** VPP checks `pool_is_free_index` before it compares the slot, and an add on a bound slot returns 0
   and changes nothing (`in_out_acl.c:94-121`). For each slot:
   - (a) unbind P: this succeeds only if the slot names P's index (a freed index the probe popped back). The binding is
     removed and reported as Freed.
   - (b) bind P, then unbind P: this succeeds exactly when the slot was empty, and leaves it empty.
   - (c) otherwise the slot holds some other table: try an unbind through each existing table, then through each freed index
     popped one by one.

   P is an empty placeholder (misses go to the node's default next). It is bound only on an empty slot of the given interface,
   for two API calls.
3. **Resurrection.** When a binding names a freed index, or a proven output-ACL slot matched no existing table, the run pops
   the LIFO free list **down to that index** and unbinds through it. Then every placeholder is deleted in reverse creation
   order, which restores the free list exactly. A freed index is on the free list, so this never pops a fresh one. Two
   exceptions:
   - (a) the probe table on a pool that has no free index at all: one index, once per VPP instance, reused by every later run;
   - (b) one pop after another client took the awaited index. A pop above every index seen re-reads `classify_table_ids`, and
     the tables that appeared meanwhile are tried (TestHoleTakenBySomeoneElse).
4. **Bound.** `MaxPlaceholders` = 64 per run, probe included. A binding whose freed index is deeper in the free list is
   Unclearable, and the run is Capped (`ErrUnclearable` + `ErrCapped`, which wraps `ErrNoCleanIndex`).
5. **Acquire.** It still quarantines every Unclearable index. It now **retries after a capped quarantine**, because the cap
   is a property of that index's binding, no longer of the pool.
6. **Delete phase.** Same readbacks, with on-demand resurrection. What cannot be removed is logged and counted, not returned
   as an error.
7. **Metrics.** New `vrx_agent_iface_sanitize_placeholders_total{phase}` (one per run, plus pops). The help text of
   `vrx_agent_iface_sanitize_capped_total` is updated.
8. **Removed:** `FreshRun`, `PlaceholderCap`, `Report.Holes`. Added: `Report.Pops`, `Report.Wanted`. `Cap` is now
   `MaxPlaceholders`.
9. **Test model (`sanitizetest`).** `Model.Pool()` added. `policer_classify_dump` and `flow_classify_dump` now answer with VPP
   26.06's semantics. Both dumps are in `Messages`.
10. **Docs.** The `sanitize.go` package header is rewritten. `docs/vpp-code-track.md` V19 (fallback column) and V23 (item and
    fallback b) are updated.

Cost of a clean create went from 110 API calls (TD-3 re-review, one live table) to **35**. The VPP journal went from about 59
lines per sanitize run to **6** (3 unbind warnings, each logged twice).

**Why a placeholder-free read of the free list is impossible (so this is the proof):**
- VPP 26.06 exposes neither the classify pool's vector length nor its free list. `classify_table_ids` and `show classify
  tables` walk live tables only, and `pool_is_free_index` returns 1 for any index beyond the vector.
- A free-list entry at the tail and a fresh index are therefore indistinguishable by popping.

The evidence rests on four facts:
- (a) every sanitize run popped exactly one index;
- (b) that index, 22, came from the free list: the base run shows 122 freed indices, and 22 is below indices it popped, 120
  and 121;
- (c) the run deleted it again as the last placeholder, so it went back on top;
- (d) the old algorithm's own count of freed indices, and its pop order, are unchanged before and after.
