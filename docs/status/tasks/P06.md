| P06 § | where | notes |
|---|---|---|
| 1 persistence | `src/db/schema.ts`, `migrations/0000_init.sql` (+ drizzle meta), `src/db/db.ts`, seed in `auth.service.ts` | **Drizzle** + `pg`; the 7 tables of docs/04 + `config_pending` (the one unconfirmed commit, proto.md §4); migrations applied at boot; first admin from `VRX_BOOTSTRAP_ADMIN_PASSWORD` when `app_user` is empty (D-048). DSN from `VRX_DATABASE_URL` (or pg-test's `VRX_PG_DSN`). Lazy pool: the app builds without a DB (OpenAPI gen, route test). |
| 2 datastore | `src/datastore/*` | `getRunning / getCandidate / patchCandidate (RFC 7386 at a pointer) / putCandidate / deleteCandidate / diff / discard`, import, admin break-lock. Single-writer lock (owner + timestamp, `SELECT … FOR UPDATE`, stale after `VRX_LOCK_TTL_SEC`), 409 problem with `lock{owner,…}`. Every stored candidate is schema-valid (tier a on the write path). |
| 3 validation | `src/commit/validation.service.ts` | schema → semantic (`validateConfig` of packages/schema + secret-ref existence, D-051) → agent `DryRun`; problem+json `errors[]{pointer,message,rule?}`, `tier`, `warnings`. `MergePatchError` → 400 with pointer (D-070). |
| 4 commit engine | `src/commit/commit.service.ts` | validate → `Apply(txn)` (owner stated, subsystems = agent's implemented ∩ ROOT_KEYS) → APPLIED: revision (full redacted snapshot, sha256 of canonical JSON, author, comment, parent, txn id, kind) + candidate promoted + `app_user` synced from `management.users`; FAILED/ROLLED_BACK/DEGRADED → 422 with per-object results, running untouched. `?confirm=<sec>` → pending until `POST /commit/confirm`; revert detected from `CONFIRM_REVERTED` or Health after the deadline. `POST /rollback/{rev}` = new revision with the old payload, applied. Revisions/export/import. Commit/confirm/rollback serialised. |
| 5 routes | `src/config`, `src/state`, `src/actions`, `src/secrets`, `src/audit` | `/api/v1/config/**` incl. generic `GET/PATCH/PUT/DELETE /api/v1/config/{path…}` (path = JSON pointer, first segment ∈ ROOT_KEYS — no controller per domain); `/state/{system,interfaces,routes?vrf=&page=&pageSize=,drift,events}`, `/state/neighbors` 501 (no agent RPC — questions #1); `/actions/{action}` 501; `/secrets` (values in, never out); `/audit` (admin). |
| 6 auth | `src/auth/*` | argon2id (`@node-rs/argon2`, OWASP profile), HS256 JWT access 15 min (`jose`), rotating refresh token in an httpOnly SameSite=Strict cookie scoped to `/api/v1/auth` (hashed in Valkey, single use, replay revokes the family), API keys `Authorization: ApiKey vrxk_…` (sha256 at rest, role-capped, expiry), global `AuthGuard` (readonly = GET only, operator = everything except users/AAA — enforced on the resulting document, admin-only routes via `@MinRole`), login rate limit per IP (Valkey), lockout after 10 failures. |
| 7 audit | `src/audit/audit.interceptor.ts` | one `audit_log` row per mutation: user, source IP, route pattern, resource (pointer), redacted before/after, result, HTTP status; 403s audited by the guard; logins audited with the real failure reason. |
| 8 relay | `src/telemetry/*` | one upstream `StreamEvents` (always, reconnect/backoff) + `StreamStats` only while someone listens; `WS /api/v1/stream`, auth before the upgrade (header or subprotocol `bearer.<jwt>`), `{subscribe|unsubscribe:[topics]}`, per-connection topic filter, JSON heartbeat + ping/pong. Topics: `iface.counters, worker.cpu, link.events, reconcile.events, commit.events, agent.events`. |
| 9 OpenAPI | `src/app.ts` (`buildOpenApi`), `packages/api-client` | OpenAPI **3.1** from Nest decorators; request/response DTOs are Zod (`openapi()`), config components are the Zod domain schemas of packages/schema (`RootConfig` references the 13 `<Key>Config`), `Problem` (RFC 9457). `pnpm gen` regenerates `packages/api-client/src/generated/schema.d.ts`; `lint` runs `redocly lint`. |
| 10 tests | `src/**/*.test.ts` (unit), `test/e2e/*` (host PG + Valkey + fake agent), `test/integration/agent.int.test.ts` | see below; scripts `test`, `test:e2e`, `test:integration`. |

Secrets never leave the write path: GET/diff/revisions/export/audit use `redactSecrets` (D-046/D-070), hashes live only in
`app_user`, the round-trip rule keeps an omitted `passwordHash`, the agent gets `DesiredState.fromJSON(redact(config))`
(D-040), secret values are AES-256-GCM under a 0600 key file.

## Decisions (for the LOG)
| id | decision | options | why |
|---|---|---|---|
| D-P06-1 | Persistence = **Drizzle ORM + node-postgres**, SQL migrations generated by drizzle-kit and committed, applied at boot by drizzle's migrator | (a) Prisma (b) Drizzle (c) raw SQL | no query-engine binary / postinstall (shared pnpm store, `allowBuilds`), TS-first schema, plain SQL migrations reviewable in git |
| D-P06-2 | Candidate = one singleton row, single writer; lock goes stale after `VRX_LOCK_TTL_SEC` (1800) and can be taken over (candidate kept); admin can break a lock (candidate discarded) | (a) per-user candidates (b) singleton + stale takeover (c) no expiry | P06 §2; (c) strands the box when an admin walks away |
| D-P06-3 | Revisions store the **redacted** document; password hashes live only in `app_user` and are hydrated back for validation; a config commit makes `app_user` follow `management.users` (config-sourced users removed, bootstrap admin kept) | (a) hashes in revisions (b) redacted revisions + app_user | D-046/D-070: revisions are shown/exported; one place for credentials |
| D-P06-4 | Operator restriction is enforced on the **resulting document** (`/management/users`, `/management/aaa` must be unchanged), not on the URL | (a) URL prefix check (b) document check | PUT/import/rollback at the root cannot bypass it |
| D-P06-5 | Confirmed commit held in `config_pending`; revision written only after CONFIRMED; revert learnt from `CONFIRM_REVERTED` or Health after deadline+1.5 s; candidate kept after a revert | (a) write revision at APPLIED and mark reverted (b) pending table | proto.md §4 ("persisted only after CONFIRMED") |
| D-P06-6 | Apply sends the whole document with `subsystems = HealthResponse.subsystems ∩ ROOT_KEYS`; unimplemented domains are reported as `notApplied` | (a) all keys (UNIMPLEMENTED) (b) implemented only (c) refuse | lets P06 work with a partial agent build; visible to the client |
| D-P06-7 | Refresh tokens: opaque, hashed in Valkey with rotation families (reuse ⇒ family revoked); login rate limit in Valkey; lockout counters in PostgreSQL | (a) JWT refresh (b) DB table (c) Valkey | Valkey is the stack's ephemeral store; lockout must survive restarts |
| D-P06-8 | Secret store: AES-256-GCM, master key in a 0600 file (`VRX_SECRET_KEY_FILE`, created on first use); `POST/GET/DELETE /api/v1/secrets`, values never returned, referenced secrets cannot be deleted | (a) env key (b) key file (c) KMS | rule 10; no KMS on the appliance |
| D-P06-9 | WebSocket auth before the upgrade (Fastify `preValidation`): `Authorization` header or subprotocols `vrx.v1, bearer.<jwt>`; never a token in the URL | (a) query token (b) subprotocol (c) cookie | URLs land in logs; browsers cannot set WS headers |
| D-P06-10 | OpenAPI 3.1 with Zod-derived DTOs; `RootConfig` component references the 13 domain components; `packages/api-client` gen builds the API's deps itself and `@ngfw/api` became its devDependency (turbo orders `gen`) | — | one schema, three consumers; the old gen raced proto/schema generation |
| D-P06-11 | apps/api `eslint.config.js` adds decorator-aware parser options (consistent-type-imports would break Nest DI) and allows `any` in `test/` only | — | zero-warning lint without `import type` on injected classes |
| D-P06-12 | Task-branch history recreated once (2 commits instead of 5 WIP commits): gitleaks flagged literal e2e test passwords; tests now generate credentials per run | (a) allow-list (b) recreate commits | tools/ci.sh: "recreate the commits without it"; same as D-067 for P02c; never on main |
