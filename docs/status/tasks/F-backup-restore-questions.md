# F-backup-restore implementation choices

Historical backup=7 allocation is occupied by integrated management.notifications=7. Use new additive tags backup=8, templates=9; preserve all existing fields.
Templates live in the configuration document: edits and apply use normal candidate locking, validation and commit. Accounts, API keys and MFA account restoration are excluded (D-097/D-102); imported password hashes are discarded by the datastore. Options considered: transactional document vs independent table; document avoids a separate write source and keeps rollback semantics.
Backups contain last 30 days audit records (bounded export) and decrypt/re-encrypt secret values inside the outer passphrase authenticated encryption, so a different destination master key is supported. No original key required.

Implementation gaps discovered: the existing candidate had no place for inactive restored secret pins. Added candidate.restoreSecrets + ConfigTx stage hook + normal commit version selection; source core edits preserve the existing security/commit architecture and manager authorized these seams. Shared per-ref advisory transaction locking with Secrets.put prevents version allocation races. Dedicated ngfw-upgrade@{stage,activate,confirm,rollback} root units execute the existing signed-image mechanism because the agent sandbox is intentionally read-only outside its original paths; agent sandbox/capability settings remain unchanged. Unit installation executes no upgrade and no host service was started.

Archive extension is `.ngfwbackup`, a versioned bounded gzip JSON archive sealed with scrypt/AES-256-GCM; it does not falsely advertise age/tar.zst interoperability. The prompt's envelope explicitly permits gzip. Secret values are decrypted only within archive construction and re-encrypted with the destination's existing master key as inactive versions during restore. HTTPS receiver retention is explicit receiver policy via x-ngfw-backup-retention; automatic remote deletion is implemented for SFTP and local only. Inline credentials/password hashes are forbidden in template JSON patches; passphrase/secret references are supported.
