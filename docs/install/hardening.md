# Appliance hardening profiles

The NGFW package ships a CIS-inspired baseline, systemd profiles and a pinned APT
repository verifier under `/usr/lib/ngfw/hardening`. These profiles are staged
into an **offline appliance root** with `stage.py --root /path/to/offline-root`.
The command rejects `/`, aliased roots and symlink destinations; it neither
reloads a service nor applies sysctl to the build host. It is intentionally
opt-in until real daemon smoke tests pass on the appliance. It does not claim CIS
certification, penetration testing or secure boot.

| Area / CIS-inspired family | Control | Exceptions and activation |
|---|---|---|
| 1.5 kernel disclosure | kptr_restrict=2, dmesg_restrict=1, unprivileged BPF disabled | Root VPP BPF unaffected; appliance smoke required |
| 1.1 filesystem | Protected hardlinks/symlinks, FIFOs/regular files; six unused filesystems blocked | Boot and network modules retained |
| 5.1 SSH | Key-only SSH, no root password login, no forwarding, 3 attempts | `--ssh-key-only` requires provisioned root authorized_keys; console bootstrap retained |
| 3.3 management ingress | Explicit management-interface loose rp_filter | `--management-interface mgmt0`; never supply linux-cp taps; nftables renderer owns management filtering |
| Service isolation | No new privileges; readonly filesystem/home; bounded capabilities/address families; syscall filters | Writable daemon configuration/state retained; agent/FRR mount+namespace access retained |
| PostgreSQL | Template-instance sandbox | `postgresql@.service.d`, not only the no-op umbrella service |
| 5 password/PAM, 4 auditd | Existing distro policy/API mutation audit | Extra PAM/auditd packages absent from pinned pool; not silently installed |
| AppArmor, cron/at | Retain distro profiles and image package policy | Runtime enforcement/service removal remains appliance acceptance |
| VPP | Existing product unit unchanged | No VPP sandbox profile supplied |

No SSH cipher/KEX allowlist is frozen: distribution crypto policy can evolve
without pinning obsolete algorithms. A boot image must provision keys before
requesting SSH key-only mode. Neither installer root passwords nor signing keys
are copied into profiles. Baseline installation does not change firewall policy:
`inet ngfw` is generated by the existing nftables renderer.

`check.sh --root /path/to/root [--json]` is a read-only configuration inspection.
It prints PASS/FAIL and explicit EXCEPTION entries and exits 1 for a failed
required control. PASS verifies staged file contents, not active kernel values,
SSH precedence or daemon health. After staging, verify effective SSH config with
`sshd -T`, sysctl values and each daemon on a disposable appliance before release.

Offline systemd 259 scoring of copied unit fixtures gave API 3.0 → 1.7 and agent
5.0 → 3.8. Scoring is an exposure estimate, not compatibility proof. FRR retains
NET_ADMIN/NET_RAW/SYS_ADMIN for networking and namespaces; Kea retains AF_PACKET;
chrony retains SYS_TIME and hardware devices inherited from its unit; the agent
retains AF_NETLINK and writable renderer directories. MemoryDenyWriteExecute is
not added to the Node JIT process. Unit-specific runtime verification remains in
the central deferred acceptance report; enable profiles only after that gate.

## Signed repository verification and rotation

Use an authenticated public keyring:

```sh
python3 /usr/lib/ngfw/hardening/signing/verify.py \
  --repository /path/to/apt --suite resolute \
  --keyring /path/to/authenticated/ngfw-archive-keyring.gpg
```

The verifier requires detached `Release.gpg`, verifies with gpgv against only
that keyring in a temporary home, and checks the signed SHA256 index members. It
refuses missing signatures, unknown keys, tampered metadata/indexes and escaping
or duplicate paths. APT then validates package hashes from the signed indexes;
use only a `signed-by=/usr/share/keyrings/ngfw-archive-keyring.gpg` source. The
helper does not replace APT's package-content verification or install anything.
P10's `scripts/publish-apt.sh` remains the sole repository producer.

For key rotation: distribute the new public key through the authenticated
provisioning channel, temporarily provision both public keys in the pinned
keyring, sign the next repository with the new private key outside the source
checkout, verify it and perform a disposable APT installation, then remove the
old public key after clients have migrated. Retain old signed repos for rollback
as policy permits. Never place a private key in the image or repository. Tests
use an ephemeral Ed25519 key and stop its own gpg-agent.

Run `deploy/hardening/tests/run.sh` for the host-independent tests. Full signed
APT install and runtime/service/AppArmor compatibility are acceptance checks on
an offline-built disposable appliance; this work does not modify the shared host.
