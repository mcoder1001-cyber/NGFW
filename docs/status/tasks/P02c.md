## What was built

Full models for the four group-(c) root keys (docs/04 shapes, WBS D6.2/D6.5/D6.6/D7.1/D7.3/D7.5/D9.1 plus the docs/04 keys lldp/ipfix and
D6.4/D6.9/D7.4/D7.6/D9.2 kept minimal), documented field-by-field in `docs/contracts/schema-vpn-tunnels-services-ha.md`:

- **vpn** — `ipsec { settings, proposals{ ike, esp }, tunnels{ … } }` in the P11 §2 shape (`localAddr, remoteAddr|%any, localId, remoteId,
  auth{psk(secretRef)|cert}, proposal, localTs[], remoteTs[], ikeVersion 1|2, dpd, natT, mobike, mode, rekey, startAction, vrf,
  routeBased{ipipInterface}`), AEAD/integrity consistency, `wireguard.interfaces{ peers{} }` (public keys validated as exactly 32 base64 bytes,
  private/preshared keys as references), `pki { cas, certificates, hsm }` (references only, ACME), `remoteAccess{}` (IKEv2 + EAP, pools).
- **tunnels** — `gre{}` (l3/teb/erspan), `vxlan{}` (vni, ports, multicast + mcastInterface, decap), `ipip{}` (p2p/p2mp, dscp); every tunnel has
  `underlayVrf` + `vrf`, optional `instance` (fixes the VPP name so other domains can reference it), interface addresses.
- **services** — `dhcp { servers{} (Kea instances: vrf, interfaces, subnets{pools, reservations, options}), relays{} }`, `dns { resolvers{}
  (Unbound instances: listen, access control, forwarders/DoT, forward zones, local zones with typed records, DNSSEC, cache), vppCache }`,
  `snmp` (communities and USM keys as references, v3 users, trap receivers), `lldp`, `ipfix { exporters{}, flowprobe, sflow }`, `ntp` (chrony).
  "One Kea/Unbound instance per X" is the record key + `vrf` + bind set (vdom.md #5).
- **ha** — `vrrp[]` (VRRPv3: interface, vrId, family, priority, interval in ms, preempt/accept, unicast peers, addresses, tracking, engine
  vpp|keepalived), `cluster` (membership, config sync, state-sync flags, key as reference).
- **26 semantic validators** (`vpn.*` 9, `tunnels.*` 7, `services.*` 6, `ha.*` 4) — proposals/PKI/IPIP references exist, VRFs exist, local /
  source / bind addresses configured on an interface in the right VRF, route-based IPsec ↔ IPIP consistency, peer/instance/socket/VRID
  uniqueness, DHCP subnet within an interface prefix and non-overlapping, DNS listen sockets unique per VRF, VRRP virtual addresses claimed once
  and inside the interface prefix, and a group-wide inline-secret scan (PEM banners, 32-byte base64 blobs).
- `semantic/tunnels-common.ts`: pure IPv4/IPv6 math + duck-typed lookups into `interfaces`/`vrfs` (work with the P02s placeholders and P02a's
  future models alike).
- 9 test files / 319 new tests (483 total in the package) with hostile inputs: inline `psk`/`password`/`privateKey`/`community`/`key`, PEM
  in refs, 43/45-char and wrong-padding WireGuard keys, `%any` + start, MOBIKE on IKEv1, mixed families, multicast/unspecified endpoints,
  VNI 2^24, VRID 0/256, priority 256, 15 ms interval, pools outside subnets, duplicate MAC with different case/separator, DUID on v4,
  forwarder == listen (loop), Kea/Unbound passthrough keys, control characters, etc.
- 19 example fixtures: 7 valid, 5 `invalid-*` (schema-rejected), 4 `<domain>-semantic-<rule>.json` (schema-valid, one finding each).
