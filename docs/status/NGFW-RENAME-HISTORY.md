# NGFW naming and historical execution evidence

The owner explicitly authorizes the complete product and technical namespace rename. Current source names, package/service IDs, environment variables, contracts, SDK names, paths and documentation use NGFW. Host-installed services, existing databases, credentials, licences and physical lab machines are not migrated by a source change.
Historical status/decision prose has been normalized to the new terminology. This normalized presentation does not claim that previously built binaries or signed data were rebuilt or renamed. Original literal execution records remain preserved in Git before this rename (base0d174caf96413599a6bae7111bf74d14ecebede1 and existing archive refs). Original build manifests, cryptographic inputs and output archives remain byte-exact outside the source tree. Only freshly built and verified NGFW outputs may be presented as renamed packages.
The change requires a coordinated new installation or separately planned migration of runtime state, service accounts, stored licence formats, issued tokens, client protocol names and external integrations. No implicit old-namespace acceptance is added and authentication/privilege policy stays the same. Laboratory-only acceptance remains deferred; real compilation/test failures must be corrected and complete mandatory quick remains required.
