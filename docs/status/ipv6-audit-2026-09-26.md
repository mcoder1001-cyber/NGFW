# IPv6 audit — 2026-09-26

Question from the product owner: does the whole system accept IPv6 everywhere? Checked on main 8eeae29 + this branch.

**Answer: yes, with two fixes in this change and three follow-ups owned by rows that have not started.**

## What was checked

| Layer | Result |
|---|---|
| Schema primitives (`packages/schema/src/primitives.ts`, `ip.ts`) | `ipAddress`, `ipCidr`, `ipNetwork`, `hostOrIp` are v4 ∪ v6; `canonicalIp`/`canonicalPrefix` are RFC 5952 |
| Schema fields that accept IPv4 only | every one is IPv4 by definition or has an IPv6 twin: NAT44/DET44/DS-Lite/MAP (IPv4 side), proxy-ARP ranges, DNS A records, OSPF area ids, RIPv2 networks; interfaces, tunnels and LLDP carry `ipv4` + `ipv6` |
| Dual-stack protocols | static routes, prefix lists, BGP (`ipv4Unicast` + `ipv6Unicast`), Kea DHCPv4/v6, RA/ND, WireGuard, ACL, host ACL, syslog/NTP/DNS servers, IPFIX/sFlow collectors |
| Agent (Go, 119 `Is4`/`To4` sites) | family checks (both ends of a tunnel/BFD/ACL rule in one family) or IPv4-only features (NAT44 sessions, IGMP, DET44); TAP and LLDP carry both families. The IPFIX **default** exporter is IPv4-only in VPP — IPv6 collectors go through additional exporters and the schema says so (`services.ipfix-sflow-*` validators) |
| Host firewall (nftables renderer) | `inet` tables (one rule set for both families); ICMPv6 ND/RA always allowed |
| API | loopback = `127.0.0.0/8`, `::1`, `::ffff:127.*`; trusted-proxy walk and audit use the real client address; rate limits and lockout key IPv6 clients by their /64 |

## Fixed in this change
1. **WireGuard client config** (`apps/web/src/domains/vpn/wireguard/model.ts`): `networkOf` cleared host bits for IPv4 only, so a
   generated `AllowedIPs` could carry `2001:db8::1/64`. It now uses the schema's `canonicalPrefix` for both families (test added).
2. **`tools/app`**: the web UI listened on `0.0.0.0` (IPv4 only). The default is now `::` (dual-stack) when the kernel has IPv6,
   else `0.0.0.0` (listening on `::` fails with EAFNOSUPPORT when IPv6 is off — verified in the cloud container). `status` prints
   `http://[addr]:port/` URLs for IPv6.

## Follow-ups (owned by rows that have not started)
- **P10** (product packaging): the product web/API listener must be dual-stack with the same IPv6-off fallback.
- **F-ospf**: the OSPF schema is a stub — OSPFv3 (IPv6) is in the row's title and must land with it.
- **F-isis-rip**: RIPng is in the row's title; today's `rip.networks` is IPv4-only (RIPv2).
- **F-igmp-mfib**: IGMP is IPv4 by definition; the IPv6 counterpart (MLD) is not in any row — decide when that row starts.
