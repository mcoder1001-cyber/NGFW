# Actual API/browser campaign handoff

This is an execution recipe, not an acceptance receipt. Supplier readiness and the canonical packet campaign remain prerequisites. The API caller is the manager; the independent QEMU coordinator owns the guest. No fake agent, database seed, direct sealed-store staging, or disabled licence guard is permitted.

## Licence and private inputs

Before API startup set `NGFW_LICENSE_FILE` to the owned API run directory, `NGFW_LICENSE_PUBKEY_FILE` to a fresh fixture public key there, and `NGFW_LICENSE_SERIAL` to a fresh fixture serial. Never use the default host licence path. Use the normal dependency-free `tools/license/ngfw-license.mjs keygen/issue/verify` commands with an output directory outside every Git repository, mode 0700; all credential files must be root-owned regular single-link files, mode 0600. Issue a short-lived licence bound to that serial with features `ipsec,wireguard,bgp,ospf,isis,ha` and finite limits `ipsecTunnels=10`, `wireguardInterfaces=10`. Upload the generated signed file through authenticated administrator `PUT /api/v1/system/license`; require `GET /api/v1/state/license` status `valid`. Signing is Ed25519 over recursively sorted canonical UTF-8 JSON of `license`; the wrapper is `{format:"ngfwlic/1",license,signature:<base64>}`. The fixture trust key is the normal configured verifier input, not a bypass.

Fresh PKI inputs use CA `clients`, server certificate `server` (SAN/identity `vpn.example.test`), and EAP username `client`. Keep CA private key, server private key and random EAP password outside Git and serial logs. The host caller needs certificate/key PEM; the guest peer needs only public CA PEM and the same random password. Guest handoff must be root-0600, single-link, bounded, bound to the independent guest marker's live kernel boot UUID. Never copy licence signing keys into the guest.

## Canonical transport contract

The production API client accepts a Unix socket. The fixture host listener therefore forwards bytes through mutually authenticated TLS to guest TCP host-forward 4403, and the guest forwards those bytes to the actual `/run/ngfw/agent.sock`. It does not decode or manufacture gRPC messages. Bind the host listener under the owned fixture directory, mode 0600, and configure `NGFW_AGENT_SOCKET` to it and `NGFW_AGENT_OWNER=ngfw`. Bind QEMU host forwarding to loopback only. Use fresh fixture CA/server/client certificates, require client certificates and verified peer identities, finite connection deadlines and bounded concurrent connections. The guest bridge must refuse a missing/foreign private guest marker or wrong live boot before listening. This bridge is a fixture contract; its executable and live acceptance are still pending.

## Normal candidate and secret delivery

1. Authenticate normally and retain the application's required CSRF/authentication state. Save `GET /api/v1/config` as the baseline. Require actual `GET /api/v1/state/vpn/remote-access/capabilities` to report operational readiness before enablement.
2. `POST /api/v1/actions/pki/import` with `{format:"pem",as:"ca",name:"clients",certificatePem:<public CA>,stage:true}`. Import the server with `{format:"pem",as:"certificate",name:"server",ca:"clients",certificatePem:<server>,privateKeyPem:<key>,stage:true}`. These calls create the normal versioned `cert/server` and `key/server` references; do not write secret tables.
3. `POST /api/v1/secrets` with `{kind:"password",name:"client",value:<random password>}`; require returned ref `password/client`. Never include the value in a public receipt.
4. Read the candidate after imports. Merge the public additions in `test/topology/ra-vpn/canonical-api-foundation.json` into that candidate while preserving every baseline and staged PKI field. The file is an additive fixture fragment, **not** a complete replacement RootConfig. `road.enabled` initially remains false.
5. `POST /api/v1/config/import` takes the complete merged RootConfig JSON directly, without a wrapper. `POST /api/v1/config/validate` and `POST /api/v1/config/commit` take no body. Require validation `ok=true`, then commit `status=applied` or `unchanged` with `sync.state=in-sync`; reject partial/not-applied results. No asynchronous job ID is returned by this controller: commit awaits apply. A `pending` result means a confirmation window, not a background job. This campaign omits `?confirm`; if an explicit confirmation window is chosen, inspect `GET /config/commit/pending`, then call `POST /config/commit/confirm` and require `confirmed` before proceeding.
6. `PATCH /api/v1/config/vpn/remoteAccess/road` with `{enabled:true}`, followed by the same bodyless validate/commit sequence. The real API secret delivery must populate the agent through the public Apply SecretBundle channel. Require enabled desired-state readback and actual observed session readiness, not just HTTP success.

## Browser/live peer coordination

Start the independent real EAP peer only after API enablement. Observe one `road` session through `GET /api/v1/state/vpn/remote-access/sessions?profile=road&limit=100`; counters are decimal strings and IDs are opaque 64-character lowercase hexadecimal values. Keep that real peer alive during English/Persian and light/dark browser views. Refresh must show actual sessions. Administrator disconnect uses `POST /api/v1/actions/vpn/remote-access/sessions/<observed-id>/disconnect?profile=road`; require true removal and actual zero-session readback before bounded peer reinitiation, then require a new observed session ID. Do not silently reconnect before capturing the disconnected view. Read-only users must have no disconnect action.

The standalone canonical packet driver remains a separate prerequisite: selected VRF and both ACL directions, VIP, negotiated split selectors, DNS, ESP-only wire evidence, bad password and valid/revoked/foreign TLS, original-agent restart under 30 seconds, actual connection/pool removal and complete baseline/physical rollback. The browser hold peer must not replace or weaken those assertions. Its closed reconnect coordination executable is still pending; no live browser or API campaign PASS is claimed here.
