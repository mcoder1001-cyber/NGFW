# TD-4 — contract note (api-client regeneration, additive; D-100)

`packages/api-client/src/generated/schema.d.ts` regenerated by `pnpm gen` from the TD-4 OpenAPI. Every change is
additive; no existing field is renamed, reshaped or removed, and the operation **summaries** of `Auth_login` and
`Auth_createApiKey` are unchanged (the generated CLI operation table and the SDK operations do not move):

| change | where |
|---|---|
| `POST /api/v1/auth/login` documents a **403** `application/problem+json` (`tls-required`: a password over plain HTTP from a remote peer) | D-100 (1) |
| `POST /api/v1/auth/api-keys` body gains optional `current?: string` (1–1024, write-only; required for a Bearer/JWT caller — the server answers 400 `/current` without it; not needed with `Authorization: ApiKey`) | D-100 (2) |
| `POST /api/v1/auth/api-keys` 403 description extended: `tls-required`, `forbidden` (wrong `current`), `locked` | D-100 (2) |

**Behaviour change on purpose (D-100):** a JWT caller of `POST /api/v1/auth/api-keys` that does not send `current` now
gets 400 (it got 201 before). Callers adapted on this branch: the CLI `api-key create` (password file or prompt),
`test/topology/sdk-terraform-ansible/live.sh`, the SDK doc example and the api e2e key bodies. The web UI has no
API-key screen (no caller in `apps/web`). A remote plain-HTTP login now gets 403 instead of 200/401 (see TD-4.md for
the flows that reach the API this way).

Commit: `contract(api-client): regenerate — login 403 tls-required, API-key step-up current (TD-4, D-100)`.
