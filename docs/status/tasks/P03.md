## What was built

- **`packages/proto/vrx/v1/dataplane.proto`** (2004 lines, 918 comment lines, 146 messages, 6 enums, 7 RPCs, 603 fields —
  every field commented):
  - `service Dataplane { Apply, Retrieve, DryRun, StreamStats, StreamEvents, Action, Health }` — `Health` unchanged
    (fields 1–3 identical to main, 8 fields added).
  - Transactions: `ApplyRequest{txn_id, desired_state, subsystems[], confirm_timeout_sec, confirm_txn_id, owner}`,
    `ApplyResponse{txn_id, status APPLIED|FAILED|ROLLED_BACK|DEGRADED|CONFIRMED, results[] ObjectResult{key, op, code,
    message, pointer, subsystem}, summary, validation, applied_at, confirm_deadline, message}`, `DryRunRequest`,
    `ValidationReport{txn_id, ok, errors[]{pointer, message, severity, rule}, plan[], summary}`, `RetrieveRequest{subsystems,
    owner}` → `RetrieveResponse{desired_state, subsystems, owner, retrieved_at}`.
  - Telemetry: `StreamStatsRequest{interval_ms, interfaces[], include_worker_cpu}` → `stream StatsBatch{ts, seq,
    interface_counters[]{name, sw_if_index, rx/tx packets/bytes, drops, errors, punts, rx_misses}, worker_cpu[], interval_ms}`
    (absolute counters, 1 Hz default, ≤ 1000 interfaces); `StreamEventsRequest{kinds[], interfaces[]}` → `stream Event{ts,
    seq, kind LINK_UP|LINK_DOWN|RECONCILE_START|RECONCILE_DONE|ERROR|CONFIRM_REVERTED|VPP_CONNECTED|VPP_DISCONNECTED|DEGRADED,
    interface, message, txn_id, summary, attributes}`.
  - Actions: `ActionRequest{oneof ping|traceroute|capture}` (`PingAction{target, vrf, count, size, interval_ms, timeout_ms,
    source}`, `TracerouteAction{…}`, `CaptureAction{interface, bpf, max_packets, seconds, direction, snaplen}`) →
    `stream ActionOutput{oneof line|pcap_chunk|done ActionDone{summary, exit_code, stats}}`.
  - **`DesiredState`**: one field per root key in `ROOT_KEYS` order (1–13). Fully modelled per docs/04 + P02 §2:
    `SystemConfig`, `DataplaneConfig`, `Interface`/`Subinterface` (`map<string, Interface> interfaces`), `Vrf`
    (`map<string, Vrf> vrfs`), `RoutingConfig.static[] StaticRoute{prefix, next_hops[] NextHop{address, interface?, weight},
    vrf}`, `ManagementConfig.users[] ManagementUser`. Mirrored field-by-field from the committed P02b/P02c WIP models:
    `NatConfig` (NAT44 + pools/static/identity/LB mappings, timeouts, ipfix, nat64, nat66, nptv6, det44, dslite, map, cnat),
    `ObjectsConfig` (addresses, address_groups, services, service_groups, schedules, zones, tags), `AclConfig` (lists, macip,
    host + three attachment kinds), `VpnConfig` (ipsec settings/proposals/tunnels, wireguard, pki, remote_access).
    Target-shape shells with empty sub-messages: `routing.{prefix_lists, route_maps, bgp, ospf, isis, rip, bfd}`,
    `system.{ntp, dns}`, `management.{aaa, tls, syslog[]}`, `TunnelsConfig{gre, vxlan, ipip}`, `ServicesConfig{dhcp, dns,
    snmp, lldp, ipfix}`, `HaConfig{vrrp[]}`.
  - Mirror rules (documented in the file header and `docs/contracts/proto.md` §1): snake_case of the Zod names (protobuf
    JSON name == Zod name), records → `map<string, X>`, Zod enums → `string` with the values in the comment, `.optional()`
    scalars → proto3 `optional`, discriminated unions flattened. **Property proven by the tests: the protobuf JSON of a
    parsed `RootConfig` document is a `DesiredState`** (strict `protojson.Unmarshal` / `DesiredState.fromJSON`).
- **Tooling** (`packages/proto/`): `buf.yaml` (STANDARD − SERVICE_SUFFIX − RPC_RESPONSE_STANDARD_NAME, breaking FILE),
  `buf.gen.yaml` (ts-proto now `include_imports` + `include_wkt` for `google.protobuf.Timestamp`; Go uses `timestamppb`),
  `gen.sh` (deletes only `*.pb.go`, so the hand-written Go test next to the stubs survives `pnpm gen`), `package.json`
  (`test: vitest run`, `vitest ^3` devDependency → `pnpm-lock.yaml` updated), `tsconfig.json` includes `test/`.
- **Generated stubs committed**: `apps/agent/gen/vrx/v1/dataplane.pb.go` (13047 lines), `dataplane_grpc.pb.go` (414),
  `packages/proto/gen/ts/vrx/v1/dataplane.ts` (24835), `packages/proto/gen/ts/google/protobuf/timestamp.ts` (235).
- **Compile-check tests**: `apps/agent/gen/vrx/v1/desiredstate_test.go` (4 tests: root-key/field-number pinning; every
  valid `packages/schema/examples/*.json` through strict protojson + binary and JSON round trips; value assertions on
  `two-interfaces.json`; typed construction across all 13 domains + envelopes) and `packages/proto/test/desired-state.test.ts`
  (7 tests: same coverage with ts-proto `fromJSON/encode/decode/toJSON/fromPartial`, JSON names == Zod names).
- **`docs/contracts/proto.md`**: DesiredState projection rules, Apply (idempotency: declarative + `txn_id` retry, subsystem

## Decisions taken (for docs/decisions/LOG.md)

| id | decision | options considered | why | reversal cost |
|---|---|---|---|---|
| D-P03-1 | `DesiredState` is a strict 1:1 JSON-compatible projection of `RootConfig` (snake_case names, records→maps, arrays→repeated, Zod enums→`string`, `.optional()`→proto3 `optional`, unions flattened); proven by strict protojson/`fromJSON` tests on the schema examples | (a) proto enums + hand-written per-domain mapper in the API (b) JSON-compatible mirror, strings for enums | (b) zero mapping code in P06 and the tests, new Zod enum values need no proto change, `diff(running, actual)` works on `toJSON()`; Go loses enum exhaustiveness (descriptors switch on documented strings) | medium after `contracts-v1` (retyping fields), minutes before |
| D-P03-2 | Record-shaped domains `interfaces`/`vrfs` are `map<string, Interface>` / `map<string, Vrf>` fields on `DesiredState`; the other 11 domains are `<Key>Config` messages | (a) `InterfacesConfig{map entries}` wrappers for all 13 (b) maps for the two records | (a) breaks the JSON projection (`{interfaces:{interfaces:…}}`) and needs a transform in every consumer | low |
| D-P03-3 | buf lint = STANDARD − SERVICE_SUFFIX (D-008) − `RPC_RESPONSE_STANDARD_NAME`; stream element types keep docs/04 names (`StatsBatch`, `Event`, `ActionOutput`, `ValidationReport`); request types are standard (`DryRunRequest`, `StreamStatsRequest`, `StreamEventsRequest`) | (a) `StreamStatsResponse{batch}` wrappers (b) rename to `<Rpc>Response` (c) except the rule | (c) keeps the names P05/P06 prompts use and avoids an indirection in every stream loop; same rationale as D-008 | trivial (pre-v1 rename) |
| D-P03-4 | `Retrieve` returns `RetrieveResponse{desired_state, subsystems, owner, retrieved_at}`; `DryRun` takes its own `DryRunRequest` (no confirm fields) | (a) bare `DesiredState` / reuse `ApplyRequest` as sketched | metadata says which subsystems were really dumped; `RPC_REQUEST_RESPONSE_UNIQUE`; a dry run is not a transaction | trivial |
| D-P03-5 | Unmodelled domains mirror the **committed P02b/P02c WIP** (`task/P02b@ec0ccda`, `task/P02c@b815d15`) rather than docs/04's literal top-level sketch; P02a domains and tunnels/services/ha carry the documented target shapes with empty sub-messages | (a) docs/04 literal (`nat.static/portForwards/cgnat`) (b) empty `<Key>Config{}` shells only (c) mirror WIP | (a) would be dead on arrival (P02b's model has none of those names); (b) gives DF-*/P11 nothing to code against; (c) most likely to survive, follow-up is a mechanical diff | low (pre-v1) |
| D-P03-6 | No proto `reserved` ranges for planned fields; numbering convention in comments (Zod fields from 1 in declaration order, agent-only annotations from 100) | (a) `reserved 1 to 99` per shell (b) comments | `reserved` means never-use; buf `RESERVED_FIELD_NO_DELETE` (FILE) would make P02b/P02c filling them in a breaking change | trivial |
| D-P03-7 | `owner` on Apply/DryRun/Retrieve is a guard: empty = agent's `VRX_OWNER`; any other value → INVALID_ARGUMENT; one owner per agent process | (a) per-request owner selecting the tag to stamp (multi-owner agent) (b) guard | (a) needs one desired.pb/confirm timer/resync per owner in P05; (b) catches a request hitting the wrong slot socket loudly | low |
| D-P03-8 | Timestamps are `google.protobuf.Timestamp` (ts-proto → `Date`, Go → `timestamppb`); ts-proto generates the WKT (`include_wkt`) for TS only | (a) `int64 unix_ms` (b) WKT | (b) idiomatic, both stacks handle it; Go must not generate the WKT (duplicate registration) | trivial |
| D-P03-9 | Apply outcomes (FAILED/ROLLED_BACK/DEGRADED) are returned with gRPC OK inside `ApplyResponse`; gRPC codes only for INVALID_ARGUMENT / FAILED_PRECONDITION / ABORTED / UNAVAILABLE / UNIMPLEMENTED; `txn_id` is a retry-idempotency key (≥ 16 remembered responses) | (a) gRPC errors for application failures (b) status in the response | (b) keeps per-object results and the validation report on the failure path; the API maps them to RFC 9457 | low |
| D-P03-10 | StatsBatch counters are absolute (not deltas); slow consumers get dropped batches visible as `seq` gaps; events have no replay and a bounded buffer with an explicit `ERROR "dropped N events"` | (a) deltas + unbounded buffering (b) absolutes + drop | (b) never blocks the data plane, loss is harmless/visible | low |
| D-P03-11 | `gen.sh` deletes only `*.pb.go` so the hand-written compile-check test can live in `apps/agent/gen/vrx/v1` (the envelope's "apps/agent/gen tests"); `vitest` added to `packages/proto` (lockfile updated) | (a) test in another package (b) keep test beside stubs | the envelope names `apps/agent/gen tests`; vitest is the repo convention | trivial |
