## What was built (apps/agent)

| area | files | notes |
|---|---|---|

| reconciler | `internal/scheduler/reconciler.go` | validate → plan (deletes reverse-topological first, then creates/updates topological; ties = registration order, key) → apply with journal → verify by re-Retrieve (2 retries) → rollback in reverse (ROLLED_BACK / DEGRADED). Scope (D-041), `ErrRecreate` with dependent re-creation, **live dependents are removed and re-created around any create/delete/recreate** (VPP refuses e.g. an interface table rebind while addresses exist), write-only descriptors (D-063), `Normalizer`, observe-only `DeleteOnAbsence()` (D-065), `Reapplier` (resync re-asserts locks), `KeyProvider` aliases |

| ownership | tags `<owner>:<name>` (loopbacks), table names `<owner>:<vrf>`, `internal/ownertable` (`owned-<owner>.json`) for routes | Retrieve filters by owner; two agents with different owners are tested on the fake and on the host |

| binaries | `cmd/vrx-agent` (env config documented in the file), `cmd/vrx-agentctl` (dev client: health/apply/confirm/dryrun/retrieve/events/stats) | socket 0660, group `VRX_SOCKET_GROUP` or primary group + warning (never groupadd); refuses to steal a live socket, replaces a stale one |

**Bug found by this simulation and fixed:** after the loss VPP kept table 7001 alive through route/interface locks
while its API lock was gone (`locks:[interface:2, recursive-resolution:1]`), so Retrieve saw a healthy VRF. Removing
the routes later would have silently dropped the VRF. Fix: `scheduler.Reapplier` (resync re-asserts the idempotent
`ip_table_add_del` add) and VRF `Update` re-adds both families. Re-run: both families show `locks:[interface:2, API:1, ...]`
after the loss restart (end of `P05-evidence.txt`).

## Out of scope / left undone
- **Interface attributes** (enabled/MTU/MAC/rx-mode/promiscuous/unnumbered/subinterfaces/dhcpClient/description) are
  DF-1/P08: the projection ignores them, DryRun reports `agent.unsupported-field` warnings, Retrieve leaves them unset —
  the API's running-vs-actual diff will show those leaves until P08 wires DF-1. VRF and route `description` likewise.
- **DF-1 alias wiring (D-065):** when DF-1 merges, the wiring must register its `interface` alias descriptor, set
  `core.Env.IfRef = core.AliasInterfaceRef`, and have the projection emit an `interface/<name>` object per document
  interface (creator key for loopbacks). Until then core objects depend on `interface.loopback/<n>` directly.
- `StreamStats.worker_cpu` is not filled (the host has no workers; counters per interface are).
- VPP reconnect resync is proven with a fake connection only (no VPP restart allowed, D-012).
- Routes in the shared table 0 are attributed by the owner table; VPP's API route source is shared, so another
  owner adding the same prefix in table 0 would replace our path set (slot ranges avoid it; production has one agent).
- No descriptor doc under `docs/agent/descriptors/` (outside my file set): the object ↔ message table is
  `apps/agent/internal/descriptors/core/README.md`.

## Decisions (options considered → chosen, why)
| id | decision | options | why |
|---|---|---|---|
| D-P05-1 | Core descriptor values are agent-internal protos (`core_model.proto`) + one projection `DesiredState ⇄ KVs` | (a) vrx.v1 messages directly (b) DesiredState fragments (c) internal messages + projection | (a) loses keys (VRF name, table id) and the diff granularity; (c) is what DF-* do (D-055) |
| D-P05-2 | VRF key `vrf/<table id>`, VPP table name `<owner>:<vrf>`, table 0 never an object | key by name / by id | DF-2…6 depend on `vrf/<id>`; the name is recoverable from VPP |
| D-P05-3 | Route ownership = owner table `owned-<owner>.json` (added before create, removed after delete) | FIB-source filter / "all routes in owned tables" / owner table | routes have no tag; table 0 is shared; one mechanism for both |
| D-P05-4 | Execution order: deletes (reverse topological) first, then creates/updates | creates first / deletes first | frees addresses/instances before re-use; matches Ligato |
| D-P05-5 | Live dependents (incl. optional deps) are deleted before and re-created after any create/delete/recreate of their dependency | recreate only on ErrRecreate / always | VPP refuses a table rebind with addresses; stale sw_if_index in routes after a loopback re-create |
| D-P05-6 | D-063 implementation: in-process cache is the write-only descriptors' actual state; resync re-applies; delete only when removed from desired after this process applied it | persist the cache / don't delete at all | never delete on absence (D-063) while still honouring explicit removals |
| D-P05-7 | D-065: loopback no longer provides `interface/<name>`; `Env.IfRef` (direct creator key until DF-1's alias is wired); `DeleteOnAbsence()` capability; undesired observe-only objects satisfy dependencies but never constrain or get deleted/verified | keep KeyProvider alias / creator keys only / capability | manager instruction; DF-1 owns the alias |
| D-P05-8 | `scheduler.Reapplier`: resync calls idempotent `Reapply` for unchanged objects (VRF lock); VRF `Update` re-adds both families | treat as unchanged / always recreate VRF | found in the loss simulation; recreate would flap all dependents |
| D-P05-9 | Persistence = `desired.pb` + `confirmed.pb` (binary DesiredState) + `agent-state.json` (managed domains, txn history as protojson, pending deadline), atomic rename | one new internal proto / sqlite | no extra codegen, human-readable metadata, pb stays the contract type |
| D-P05-10 | Domains present in the document but not implemented are skipped (logged); only naming them in `subsystems` fails with UNIMPLEMENTED | reject any present unimplemented domain | the API sends all 13 domains (D-041); rejecting would make every full-document apply fail |
| D-P05-11 | Revert applies the confirmed baseline with subsystems = managed(pending) ∪ managed(confirmed) | confirmed domains only | a domain first introduced by the pending txn must be emptied too |
| D-P05-12 | Interface VRF binding lives in core as `interface-ip.table` | leave to DF-1 | not in DF-1's list; required for "loopbacks with IPs in your VRF range" |
| D-P05-13 | Retrieve always sets `blackhole` (derivable from the drop path), `distance` only when VPP preference ≠ 0 | omit false | Zod defaults `blackhole: false`; explicit presence keeps the diff honest (D-039) |
| D-P05-14 | Prometheus text exposition hand-written (no client_golang) | prometheus/client_golang | 7 series; avoids a dependency tree in the privileged process |
| D-P05-15 | StreamStats samples the stats segment per stream at its interval (default 1 Hz), 4-batch drop-oldest buffer | one global 1 Hz sampler | streams may ask 200 ms–60 s; segment reads are cheap (AD-5) |
| D-P05-16 | Dev client `cmd/vrx-agentctl` | grpcurl (not installed) | evidence + manager diagnostics; P13 remains the product CLI |
