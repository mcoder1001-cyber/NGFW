## What was built

| P07 § | where | notes |
|---|---|---|
| 1 login + protected routes | `auth/session.ts`, `auth/AuthProvider.tsx`, `auth/RequireAuth.tsx`, `pages/LoginPage.tsx`, `api.ts` | Access token **in memory only**. The rotating refresh token stays in P06's httpOnly cookie. A reload restores the session with one `POST /auth/refresh`. Refreshes are single-flight within a tab and use a Web Lock across tabs, because a replayed refresh token revokes the whole family. The token is refreshed at 80 % of its lifetime. An openapi-fetch middleware adds the bearer token and, on a 401, refreshes once and retries (the body is cloned). `/login?next=` accepts same-app paths only. Sign-out clears the query cache and closes the socket. A user menu shows the role, self-service password change (P06 then ends all sessions, so the UI signs out) and sign-out. The language can be switched on the login page. |
| WS auth | `packages/ui-kit/src/ws/client.ts` | The client has a new `protocols` getter, read on every (re)connect, and offers `vrx.v1, bearer.<jwt>` (D-P06-9). With no credential it stays idle instead of looping on 401s. After the relay's 4401 at token expiry it reconnects with the fresh token. P06 `{type:'error'}` frames go to `onError`. The shell subscribes to `commit.events`. |
| 7 pending-change bar | `config/PendingChangeBar.tsx`, `config/queries.ts` | Sticky bar, shown when candidate ≠ running. It polls `/config/diff` + `/config/lock` every 5 s and refetches on `commit.events`. Shows the count, "Locked by: you / X", Review diff / Commit… / Discard, and Break lock (admin, lock held by another user). Disabled buttons explain why in a tooltip: role, lock owner, or a pending confirmation. `SyncBanner` shows P06 sync `unknown`/`degraded` and "agent unreachable" honestly. |
| 7 structured diff | `config/DiffView.tsx`, `config/refine.ts` | Added / removed / changed, each with its RFC 6901 pointer, grouped by domain, values LTR in monospace. P06 diffs arrays as leaves (D-021), so `refineChanges` pairs list items on the schema's `x-vrx-ui.itemKey` (as `packages/schema/src/diff.ts` suggests). A users edit therefore shows `/management/users/1/fullName "old" → "new"` instead of two whole arrays. Reorders, duplicate keys and keyless lists stay one `replace`. |
| 7 commit dialog | `config/CommitDialog.tsx`, `config/CommitResultView.tsx`, `config/ProblemAlert.tsx` | On open: `POST /config/validate` (schema → semantic → agent DryRun). Errors are listed with pointers and block Commit; warnings and `notApplied` are shown verbatim. Then a comment field and **"Revert automatically in [2] minutes unless I confirm", default ON** (1–60 min). A result that is not pending (`applied`/`partially-applied`/`not-applied` + `notApplied` domains, warnings, sync) is shown as the server reported it. Problems show slug title + detail + `errors[]` pointers + lock owner + per-object agent results. |
| 7 confirm countdown | `config/ConfirmBanner.tsx`, `config/confirm-store.ts` | Countdown banner with Confirm. The server's `/config/commit/pending` is authoritative. The local deadline = min(request time + window, server deadline − the largest plausible clock offset from the `Date` header), so it never promises more time than there is. Kept in sessionStorage. **When the API stops answering the countdown continues locally with "Reconnecting to the device…"** (real-stack evidence below). After the window the outcome is read back, not assumed: a revision with that txn id = confirmed, otherwise "reverted — your changes are still in the candidate". |
| 8 revisions | `pages/RevisionsPage.tsx` | `ServerDataGrid` over `/config/revisions` (server paging), with a "running" chip, kind, author and comment. "Changes" (parent → rev), and compare any two revisions (diff computed from the two payloads). Rollback dialog: shows running → target diff, comment, auto-revert window default ON, `POST /config/rollback/{rev}?confirm=`. Disabled for readonly, while there are uncommitted changes (P06 `candidate-dirty`), during a pending confirmation, while another user holds the lock, and on the running revision. |
| 9 users | `pages/UsersPage.tsx` | `management.users` from candidate + running (row chips: new / changed / to be removed). Add / edit through **`<SchemaForm>` from the `management.users` item schema**; field titles, help and role names are translated. Delete. Writes `PATCH /config/management {users}` (merge-patch; omitted `passwordHash` is kept by P06's round-trip rule), then the normal bar → commit. Server pointers `/management/users/<i>/…` are mapped onto the form fields. Admin only: other roles get an info alert and disabled actions. With an empty list, "Add my account as administrator" works around the `admin-exists` rule (P06 hydrates the bootstrap hash). |
| 10 tests | see below | Vitest: session, middleware, diff refinement, countdown store, jsdom flows. Browser E2E against the real stack: `apps/web/test/e2e/flow.e2e.mjs`. |
| i18n / RTL | `locales/{en,fa}/{auth,config,revisions,users}.json` | Every string goes through `t()` (the lint rule passes). Logical CSS only (`check-logical-css` OK, 101 files). Server-authored English text in RTL alerts has `dir="auto"`. Technical values are `dir="ltr"`. |

## Decisions (for the LOG)
| id | decision | options | why |
|---|---|---|---|
| D-P07b-1 | Access token in memory only. Session restored through the refresh cookie. Refresh is single-flight + Web Lock across tabs | (a) localStorage token (b) memory + cookie | XSS cannot read the token. A concurrent refresh from two tabs would replay a refresh token and revoke the family (P06) |
| D-P07b-2 | The WS credential is a `protocols()` getter in the ui-kit client, read per connect | (a) rebuild the client on every refresh (b) getter | the relay closes at expiry (4401). The reconnect picks up the fresh token without tearing down subscriptions |
| D-P07b-3 | Countdown deadline = min(request time + window, server deadline − max clock offset). The server stays authoritative while it answers; the outcome is read back from revisions | (a) trust the server deadline (b) conservative local | the UI must keep counting when the box is gone and must never promise more time than the agent gives |
| D-P07b-4 | The diff display refines whole-array replaces per item on `x-vrx-ui.itemKey` (client side, display only) | (a) show arrays (b) refine in the UI (c) change the API diff | contracts-v1 keeps arrays as leaves (D-021). The schema comment suggests exactly this |
| D-P07b-5 | Users are edited with `PATCH /config/management {users}` (merge-patch replaces the list; P06 keeps omitted hashes by username) | (a) index pointers (b) whole list | a nested pointer cannot be passed through openapi-fetch's encoded `{path}` parameter; the whole list is atomic under the single-writer lock |
| D-P07b-6 | `apps/web/tsconfig.json` maps `@ngfw/api-client` to its source for type-checking | (a) fix api-client (not owned) (b) web mapping | without it every API call was `any` (questions #1) |
| D-P07b-7 | Browser E2E = a node script that loads `playwright-core` and Chrome from env paths | (a) `@playwright/test` dependency (b) script | no installs on the shared host. It still drives a real browser against the real stack |
