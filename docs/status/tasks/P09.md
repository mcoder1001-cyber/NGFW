## What was built

`tools/ci.sh` is **the** CI (no remote, no PRs, no CI service). Backward compatible with the manager's procedure: a bare
`tools/ci.sh` is `quick`, `tools/ci.sh --base main` is quick + contract guard.

| Command | Does |
|---|---|
| `tools/ci.sh` / `quick` | [contract guard first when `--base` is given: git-only, ~1 s] → tools present (golangci-lint, gitleaks; auto-install of the pinned versions) → `pnpm install --frozen-lockfile --prefer-offline` → `pnpm gen` + **generated-output dirty gate** limited to `packages/proto/gen apps/agent/gen packages/schema/dist packages/api-client/src/generated` (working tree vs index after gen, + untracked; `go mod tidy` drift in `apps/agent/go.{mod,sum}` also fails) → forbidden-pattern greps + gitleaks over the commit history → `turbo run lint typecheck test build` (one invocation, `VRX_INTEGRATION` unset) → `make -C apps/agent lint test build` (fails if golangci-lint silently did not run) → every Go module under `test/` in unit mode (`gofmt -l`, `go vet`, `go test -count=1`; P04 review F6) |

| `full` | quick, then: `flock -x /run/lock/vrx-lab.lock` (timeout `VRX_CI_LOCK_TIMEOUT`, 1800 s) → slot **12** from `tools/lab env 12` (validated, never eval'd; fallback = the same arithmetic, D-025) → `tools/lab status` → `tools/lab rig up w12` → lock **converted to shared** while the suites run (`VRX_INTEGRATION=1 go test -race -count=1 -timeout 20m ./...` in every Go module under `apps/agent` and `test/`; `VRX_INTEGRATION=1 pnpm -r --if-present run test:integration`) → exclusive again → `rig down w12` (also from the exit trap on failure). | `gen-check` | `pnpm gen` + dirty gate only; root `package.json` `gen:check` calls it |

## Decisions taken (for the LOG)

| id | decision | options | why |
|---|---|---|---|
| D-P09-1 | quick runs `lint typecheck test build` as **one** turbo invocation with a shared `TURBO_CACHE_DIR=~/.cache/vrx-turbo` | (a) `pnpm lint && pnpm typecheck && pnpm test && pnpm build` (b) one invocation | `gen` is `cache:false` and a dependency of all four; (a) runs it 4×. One invocation + shared cache is what makes quick 39 s warm |
| D-P09-2 | dirty gate = working tree vs **index** after `pnpm gen` (+ untracked), limited to the four generated paths | (a) `git status --porcelain` vs HEAD (b) vs index | (a) reports a staged, not-yet-committed merge as "dirty" inside the pre-merge-commit hook (observed: `M  …/.gitkeep` on a legitimate merge). (b) is identical in a plain worktree and correct in the hook |
| D-P09-3 | `full` takes the exclusive lock as a **barrier**, then holds it **shared** for rig up → suites → rig down; exports `VRX_LAB_LOCK_HELD=1 VRX_CI_FULL=1` | (a) exclusive throughout (rules §1b wording) (b) barrier + shared (c) no exclusive at all | (a) is impossible with the code that exists: P04's `tools/lab rig up` waits 120 s for a *shared* lock and dies while an exclusive holder exists (`error: rig: … held exclusively (manager ci full / VPP restart)` — evidence D4, the gate itself was the holder), and every harness takes its own `flock -s` on a fresh file description (deadlock under (a)). (b) keeps "no VPP restart underneath" and still serializes the start behind running harnesses; (c) loses the barrier. Question Q1 asks the manager to amend §1b or to route (a) through P04 |
| D-P09-4 | the pre-merge-commit hook runs `quick --base HEAD` with `VRX_CI_HEAD_REF=<ref from GIT_REFLOG_ACTION>` (contract guard + gitleaks on the branch being merged), falling back to plain quick when the ref cannot be determined | (a) hook = plain quick (task text) (b) + contract guard | `MERGE_HEAD` does not exist yet inside this hook (verified); `GIT_REFLOG_ACTION="merge <ref>"` does.
