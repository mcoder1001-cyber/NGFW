# TD-21 — Scheduler scale: index dependents per walk, heap the topological ready set

Branch `claude/modest-keller-upaw4m` (cloud session), base `origin/main`. No lab slot: pure scheduler change, unit-tested.

## Problem

D-133 / F-object-model Q9: `executor.dependents` scanned (and re-sorted) every live object for every frontier item of
its breadth-first walk — O(n²) when a base object (interface, VRF) has many dependents — and `topoThrough` re-sorted the
whole ready set on every pop (O(n² log n) for wide, flat plans). 4000 objects took 13.7 s.

## What changed (`apps/agent/internal/scheduler/reconciler.go`)

- **dependents**: builds a reverse index (dependency key → live users) once per call, then the walk only visits the
  users of the keys each frontier item provides (its key plus `ProvidedKeys`). Same set as before; the result is still
  ordered by `topo`, so the order is unchanged.
- **topoThrough**: the ready set is a `container/heap` min-heap on the same `less` (stage, registration rank, key). `less`
  is a total order, so the pop order is identical to the old sort-per-pop.
- No behaviour change; claim/ctx hunks of TD-11c/TD-9 untouched.

## Tests (`reconciler_td21_test.go`)

- `TestTD21DependentsAndTopoMatchReference`: the pre-TD-21 algorithms kept as oracles; `dependents` and `topo` give
  identical output for fan-outs of 2–301 objects (incl. alias `ProvidedKeys` dependencies).
- `TestTD21Scale`: dependents + topo over 20 000 live objects in under 5 s (≈0.1 s here).
- `BenchmarkTD21Dependents` / `BenchmarkTD21DependentsRef`: 1000 objects 3.2 ms vs 185 ms (≈57×); 4000 objects 17 ms.
- All existing scheduler tests unchanged and passing.
