# First-boot setup

Sign in as the local administrator over HTTPS. A device whose setup marker is incomplete opens the setup wizard from the dashboard. The wizard is also available at **System → Run setup wizard**. Re-running requires acknowledging that the touched configuration sections will be overwritten.

1. Choose English or Persian, an IANA time zone, and NTP servers.
2. Enter the current administrator password and a different, non-empty new password. Passwords remain in this page's memory; they are never saved in browser storage or included in the summary.
3. Choose the hostname.
4. WAN changes are optional and disabled by default. Continue without selecting an interface to preserve all existing network settings, even when no dataplane interfaces are available. To edit WAN, enable **Configure or change WAN** and review settings prefilled from the current configuration and live dataplane state. Detection uses default routes, configured NAT outside interfaces, DHCP clients and interface addresses. An ambiguous uplink requires selection. The interface, DHCP/static/PPPoE mode, address and gateway remain editable. Manual edits survive Back/Next and observation refreshes. The picker combines configured interfaces with live, unconfigured physical cards reported by the agent (dpdk, vmxnet3, virtio in the default VRF). Host-owned cards and local0 are excluded; setup does not take over the host management NIC. Failed live observations leave configured choices available. Static IPv4 requires an address/prefix and gateway. PPPoE requires an observed exclusive physical parent, ISP username and an existing `password/<name>` secret reference. Store the ISP password through the secrets editor first. Setup creates the logical `setup-pppoe` connection; the password itself is never entered here.
5. Review the scope of changes. Setup updates hostname, time and administrator password. WAN addressing and its default route change only when WAN configuration is enabled. There is no LAN creation step. Existing LAN interfaces, DHCP servers, NAT, firewall policies and management access settings are preserved. Configure internal networking and forwarding policies through their normal pages as needed.
6. Review the exact diff. Nothing is applied during Back/Next. Apply stages all settings and the administrator password together, validates the candidate through the existing engine, and makes one confirmed commit with a 120-second timer.

Check management access and select **Confirm management access** before the displayed deadline. Otherwise the configuration reverts. Confirmation promotes the new password and invalidates old credentials; sign in again using the new password. If validation or commit fails, the candidate remains available for inspection or discard through the normal configuration controls. Staging alone does not promote the running configuration or administrator password.

Completion metadata is read-only through ordinary config edits. An existing candidate must be committed or discarded first, and a changed running revision requires reloading the wizard.

API/CLI equivalent: use authenticated `POST /api/v1/config/setup/preview` with `input`, `baseRevision` (the running `x-ngfw-revision`), and a current ISO `completedAt`; stage with the same body plus write-only `current` and `password` through `/setup/stage`; then call `/api/v1/config/validate`, `/api/v1/config/commit?confirm=120`, and `/api/v1/config/commit/confirm`. To preserve the network configuration, omit all `wan*` fields. To configure WAN, provide both `wan` and `wanMode` plus mode-specific settings. The wizard omits the legacy `lan`, `lanAddress` and `dhcp` fields; older callers that explicitly supply all three retain their existing LAN setup behavior. Password-bearing requests require HTTPS or a local transport. Never pass passwords as shell command arguments or record them in command history.

For real-browser six-step English/Persian preview screenshots without applying configuration, run `apps/web/test/e2e/screens/setup.mjs` against a factory-state API with `NGFW_E2E_BASE`, `NGFW_E2E_SETUP_WAN`, `NGFW_E2E_ADMIN_PASSWORD_FILE`, and the existing Playwright/Chrome paths. This exercises server preview and stops before Apply. Native ISP negotiation, packet delivery and confirmed-commit acceptance require an isolated appliance/rig; unit verification does not establish those hardware results.

When rerunning PPPoE setup, the reserved logical WAN must still match the wizard-owned shape. An existing unrelated `setup-pppoe` interface is never overwritten. Switching back to DHCP/static removes only the unchanged wizard logical WAN; references from preserved policies must be removed explicitly first. Preview and staging recheck observed parent type and use the same atomic candidate/confirmed-commit flow.
