# Independent review of physical NIC seeding and startup order

Reviewed product source: base `d2d55984d74fa1d06c32e8271886f11f16375407`, packaging correction `2045ab8b3d2f477bb23446fb5e58b7d9d3abea3c`, integration `bde83bc87ae817a61bbc70e4029f76109ae77c35`. Independently compared the latter two across `apps`, `packages`, `deploy`, `tools`, `.github`, `package.json` and `pnpm-lock.yaml`: no differences. This is source reasoning for a post-recovery runbook; no target seeding, binding, service activation or acceptance has run.

**Verdict: seed before binding data PCI devices. Preserve names from the authoritative seed and use that running dataplane document for guarded startup.** Ordinary API edits/import cannot create built-in physical rows: `apps/api/src/datastore/physical-nics.ts` rejects marker addition, PCI/builtIn changes and row/marker removal with 403. It permits owner release/reclaim. Renaming a seeded row would entail a forbidden removal/addition; direct SQL or bypassing the guard is not an approved installation mechanism.

`SeedService` requires an empty document and no running revision, identifies at least one management PCI, and creates all non-management PCI devices plus built-in interface rows in a system commit. It retries unreachable/deferred/no-management outcomes, but stops when a revision already exists or its document is not untouched. It must therefore run before operator edits/commits. `dataNics()` takes the current kernel netdev name, otherwise `pciIfName()` returns the decimal PCI form with an explicit function suffix. Binding first would change `enp10s0` to `enp10s0f0`, and `enp1s0f0np0` to `enp1s0f0`; the current external proposals use the former kernel names.

Safe order after both filesystem/network recovery prerequisites pass:

1. Snapshot network/bridge, nftables and existing startup configuration off-host. Reconfirm explicit management IF/PCI/default routes and all data PCI names and singleton IOMMU groups. Retain kernel drivers on every data port for seeding. Stage dependency/product services under the previously reviewed suppression plan.
2. Complete canonical firstboot with bootstrap management values and credentials, and confirm durable firstboot completion. Initial `api.env` permits only database, secret-key and JWT assignments; the seeding opt-in is a post-firstboot runtime override. Firstboot calls `bootstrap-db.mjs`, not API `main.ts`; it creates the bootstrap administrator without creating an operator configuration revision. The bootstrap administrator is retained by `PgRepo.syncUsers()` when an empty configured-user list is promoted.
3. Inspect the initial rendered VPP startup (`no-pci`, management excluded), start the initial VPP/agent stack under the reviewed firewall/network safeguards, and verify agent-to-VPP binary API connectivity. The agent rejects Apply while VPP is disconnected even if HostNics inventory can be retrieved. Do not perform data PCI handover yet.
4. With no running revision and no dirty/pending candidate, add `NGFW_SEED_DEFAULT_NICS=1` to the root-owned 0600 post-firstboot API environment and start/restart API so its `SeedService.start()` runs. Keep operator edits disabled until completion. Verify the system revision and `system.seed-defaults` event, every built-in physical marker/owner/PCI, and exact management exclusions. Expected counts are seven and seventeen, subject to fresh inventory after recovery. An existing revision, deferred commit, nonempty document, unknown/degraded apply or failed seed requires investigation; do not force/recreate markers.
5. Export the authoritative running dataplane document. Compare its PCI/name map and blacklist/whitelist with the proposals; regenerate the later startup input from that document if recovery changed names. Preserve seeded names and existing physical markers. Inspect every startup preview and expected installed/new startup hash. Detach only authorized data ports from their old bridges as needed under the retained network snapshot, then perform the guarded startup/handover with explicit management probe, deadline and rollback. The management PCI and Linux route remain outside handover.
6. After VPP reconnects, require successful agent full resync, all seeded names in VPP and API live retrieval, management driver/IP/routes and a fresh root SSH connection. The agent connection hook calls `fullResync()` to reproject stored desired state after the kernel data netdevs disappear; this source path has not yet been demonstrated on these hosts. Investigate resync/alias failures before any operator revision. Only subsequently test restart/reboot persistence on clean roots with console recovery available.

`CommitService.systemCommit()` does not defer because startup preview says `restartRequired`: it defers for a busy commit lock, pending confirmation or dirty candidate. It validates, applies implemented domains, then promotes the system revision. `dataplane` is absent from agent `subsystems.Domains`, so its startup values are stored and reported in `notApplied`; no automatic VPP restart is performed by the seed. With kernel NIC names present, `desired.SplitUnboundPhysical()` excludes their VPP interface objects and emits `agent.nic-not-bound` warnings rather than alias errors. The source allows those warnings through DryRun/Apply. This yields an expected stored/partially-applied revision awaiting explicit guarded startup, not proof of working ports. A netdev lookup failure is not the same safe path: the row is kept and an absent VPP alias can fail, so retain healthy inventory/connectivity and inspect actual results.

Community licensing has no physical-NIC count or dataplane entitlement in `features/licensing/entitlements.ts`; its limits cover IPsec tunnels/WireGuard interfaces and its feature predicates cover VPN, routing and HA. Neither seven nor seventeen otherwise-empty physical-NIC seed rows needs a license. This does not assert licensed routing/HA acceptance.

No broad test was rerun for this source-only ordering review. Existing source fixtures explicitly cover the unbound physical warning path; reading them is not an independently executed test. Both targets remain blocked by root filesystem corruption, and absence of data carrier still prevents packet-forwarding acceptance.
