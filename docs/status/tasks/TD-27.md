# TD-27 — ifsanitize: clear inherited SPAN source state and LLDP on interface create (V19 family)

Branch `claude/modest-keller-upaw4m` (cloud session), base `origin/main`. No lab slot: the host proof is not run here.

## Problem

VPP 26.06 reuses a freed sw_if_index for the next interface. Two more kinds of per-index state survive the interface
delete, besides the classify and ACL bindings handled by TD-3, TD-5 and TD-25:
- **SPAN source mirrors.** These are span_main's per-index device/L2 mirror bitmaps. A new interface on the index silently
  mirrors to a stale destination, or keeps a mirror config the SPAN descriptor does not know about.
- **A stray per-interface LLDP enable.**

## What changed (`apps/agent/internal/vpp/ifsanitize/`)

| kind | how it is cleared |
|---|---|
| SPAN source (device, L2) | **Exact readback.** `sw_interface_span_dump` runs with `is_l2` 0 and then 1. Each row whose source is this index is disabled with `sw_interface_span_enable_disable` (state 0, naming its destination and `is_l2`). The dump is then read again, and any row left is **Unclearable**: the create fails closed and Acquire quarantines the index. Rows of other sources are untouched. |
| LLDP | **Blind reset** with `sw_interface_set_lldp enable=0`. It is a no-op when LLDP is not enabled. An unknown message (plugin not loaded) is recorded as Skipped. A non-zero retval is also recorded as Skipped (`lldp (retval N)`), not as an error, because LLDP is not a forwarding hazard. |

Both steps run in both phases (create and BeforeDelete), after the IPsec SPD step. The report adds `span …` rows to
Cleared and `lldp` to Reset.

**TD-25 review L1 (folded in).** A new `probeBound` flag is set after a bind of the probe placeholder P succeeds (in
the outputACL probe and in verify), and cleared once the following unbind succeeds. If that unbind fails:
- dropPlaceholders leaves P in VPP instead of deleting it under the binding, which would itself be a V19 binding to a
  freed table;
- the run's error now also carries the placeholder error. It is joined, where before it was dropped whenever the run had
  already failed.

**Test model (`sanitizetest`).**
- `Iface.Span` (per kind, destination → state) and `Iface.LLDP` are new fields.
- There are handlers for `sw_interface_span_dump`, `sw_interface_span_enable_disable` and `sw_interface_set_lldp`. They are
  added to `Messages`, so `Clean` answers them for the descriptor tests.
- `Dirty` reports both. `DeleteInterface` keeps both, as VPP does.

## Tests

- `TestInheritedSPANAndLLDPAreCleared`: plants device and L2 mirrors and LLDP on a deleted index. Checks that they are
  cleared and that another source's mirror to that index is untouched.
- `TestSPANUnclearable`: a mirror that the disable does not remove → `ErrUnclearable`.
- `TestProbeKeptWhenUnbindFails`: the unbind of P fails after the bind → P still exists and is still bound, and it is not
  deleted.
- `TestCleanInterfaceOnlyResets`: the expected Reset list now includes `lldp`.

## Verification

- `go build ./...` and `go vet ./internal/vpp/...` pass.
- `go test ./internal/vpp/ifsanitize/... ./internal/descriptors/... -count=1`: all pass.
- `golangci-lint run ./internal/vpp/ifsanitize/...`: 0 issues.
- **Lab/VPP host tests were not run** (sandbox, no VPP). Still unverified on VPP 26.06:
  - the assumption that the SPAN bitmaps and the LLDP config survive the delete;
  - that `sw_interface_span_dump` lists stale rows for a deleted/reused source index;
  - that `sw_interface_set_lldp enable=0` returns 0 on non-ethernet interfaces (loopback, tunnels). A non-zero retval
    there only lands in Skipped.

## Not done / follow-ups

- **Stale SPAN rows that name this index as the destination** (a live source that mirrors *to* the reused index) are not
  touched. They belong to another interface's config, which the SPAN descriptor owns.
