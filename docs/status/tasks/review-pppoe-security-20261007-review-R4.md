**BLOCKER R4-F1 — transition admits a new old-configuration generation.** `apps/agent/internal/renderers/pppoe/supervisor.go:79-120`; `apps/agent/internal/subsystems/pppoe.go:228-236,147-170`; `templates/ipv6.tmpl:345-347`. StopIPv6's helper holds the action lock only until stop returns. The Go caller then removes handles/replaces helper/config while old pppd is still running, with restart occurring afterwards. An IPv6-up hook can acquire the released lock in this interval and create another generation. That generation can survive the file removal/replacement or recreate up state after invalidation; an already-running Python helper keeps its old constants. Reconnect uses the same stop/remove/restart gap; Go exclusive/mutex locks do not synchronize with independent hooks. A failed apply/rollback can inherit that live generation or overwritten identity. Fix: fence hook admission through the whole stop/invalidate/replace/restart transition, or first stop the owning pppd and verify hook/client extinction before editing, with safe restart after publication. Preserve owner-scoped locks and evidence on errors. Add deterministic up-hook-after-stop/before-replacement tests for edit, removal, reconnect and failed apply/rollback. Existing paused-collection test proves revocation of one generation, not prevention of creation of another.

**MAJOR R4-F2 — pppd PID reuse keeps a dead session up.** `apps/agent/internal/renderers/pppoe/templates/ipv6.tmpl:221,278`. Refresher carries only numeric parent PID and asks whether identity(pid) is non-null; it never retains or compares the parent's original starttime/pidfd. If pppd exits and its PID is reused between polls while the PPP interface remains available, an unrelated process satisfies this condition and old generation continues reporting up. Fix: capture/verify parent identity at admission and monitor a pinned pidfd or original starttime; validate session association. Executed in-memory source probe supplied a reused parent with a different starttime; actual frozen refresh published `['up', 'down']`, demonstrating it admits up before forced fixture stop. Abrupt-loss test covers an absent PID, not reuse. No real foreign process was signalled.

Focused race tests passed (combined report). No shared VPP/host mutation, binapi edits, C code, new globals privilege or packet-trace use.
