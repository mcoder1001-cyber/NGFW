# اعلان‌ها

از بخش **مدیریت ← اعلان‌ها** کانال ایمیل SMTP یا وب‌هوک HTTPS امضاشده تعریف کنید. قاعده‌ها می‌توانند هشدار، اعمال پیکربندی، تغییر وضعیت لینک، وضعیت VPN در WireGuard یا strongSwan/IPsec و خطای دریافت فهرست مسدودسازی را به کانال‌ها بفرستند. تلگرام پشتیبانی نمی‌شود.

## ساخت و آزمایش کانال

1. با نقش مدیر، گذرواژه SMTP یا کلید امضای وب‌هوک را در **سیستم ← اسرار** ذخیره کنید. در تنظیمات کانال فقط ارجاع آن را وارد کنید؛ خود مقدار راز را در فرم کانال ننویسید.
2. کانال را اضافه و فعال کنید. برای ایمیل، سرور، درگاه، TLS یا STARTTLS، فرستنده و گیرندگان را مشخص کنید. برای وب‌هوک، نشانی HTTPS و ارجاع کلید امضا لازم است.
3. قاعده‌ای بسازید که نام کانال، رویدادها، حداقل شدت و بازه محدودیت ارسال را مشخص کند.
4. پیکربندی نامزد را ذخیره و سپس تغییرات معلق را اعمال کنید. ذخیره‌کردن به‌تنهایی کانال جدید را فعال نمی‌کند.
5. برای کانال فعال در پیکربندی جاری، **ارسال آزمایشی** را بزنید و نتیجه را در **سابقه ارسال** بررسی کنید. «تست در صف قرار گرفت» فقط پذیرش درخواست را نشان می‌دهد؛ نتیجه نهایی می‌تواند ارسال‌شده، ناموفق یا کنارگذاشته باشد.

کانالی که فقط به نامزد اضافه شده هنوز قابل آزمایش نیست. کانالی که فقط از نامزد حذف شده تا زمان اعمال حذف همچنان در پیکربندی جاری وجود دارد و قابل آزمایش است. کانال غیرفعال دکمه آزمایش ندارد. کاربران غیرمدیر می‌توانند تنظیمات و سابقه را ببینند، اما اجازه تغییر تنظیمات اعلان یا ارسال آزمایشی ندارند.

دریافت نامزد، کانال‌های فعال و سابقه ارسال هرکدام نشانگر انتظار با نام مشخص دارند. در صورت خطای دریافت پیکربندی جاری، خطای API نمایش داده می‌شود و کانال‌های نامزد جایگزین کانال‌های جاری نمی‌شوند.

## بررسی خطاها

| نتیجه یا کد خطا | اقدام |
| --- | --- |
| پیام در صف است | پس از پایان تلاش ارسال، سابقه را دوباره بررسی کنید؛ قرارگرفتن در صف تأیید تحویل نیست. |
| `secret-unavailable` | وجود ارجاع و نوع راز را در مخزن اسرار بررسی کنید. مقدار راز را فقط در همان مخزن وارد کنید. |
| `destination-rejected` | نشانی و پاسخ DNS را بررسی کنید. وب‌هوک باید مقصد عمومی HTTPS داشته باشد؛ تغییرمسیر و مقصد خصوصی یا محلی پذیرفته نمی‌شود. SMTP می‌تواند از رله خصوصی استفاده کند، با رعایت سیاست نشانی آن. |
| `smtp-failed` | دسترسی به رله، اعتبار TLS، اطلاعات حساب و مجازبودن فرستنده و گیرندگان را بررسی کنید. پاسخ خام ارائه‌دهنده در سابقه عمومی نمایش داده نمی‌شود. |
| `http-4xx` یا `http-5xx` | سیاست دسترسی و پردازش مقصد وب‌هوک و بررسی امضا با کلید تنظیم‌شده را بررسی کنید. کد واقعی وضعیت در سابقه ثبت می‌شود. |
| `delivery-timeout` یا `transport-failed` | مسیر خروجی، DNS و دسترس‌پذیری مقصد را بررسی کنید. تلاش ناموفق ممکن است تا سقف سه تلاش دوباره انجام شود. |
| `configuration-unavailable` یا `configuration-read-timeout` | دریافت پیکربندی جاری برای ارسال‌کننده ممکن نیست؛ ابتدا دسترسی API و مخزن پیکربندی را برقرار کنید. |
| کنارگذاشته | پس از تغییر پیکربندی ممکن است رویداد در صف دیگر با کانال یا قاعده فعال منطبق نباشد، یا تلاش لغو شده باشد. پیش از تکرار، پیکربندی جاری را بررسی کنید. |

## محدودیت‌های فعلی

صف حداکثر ۲۵۶ ورودی و سابقه حداکثر ۵۰۰ ورودی دارد. صف در حافظه است و پس از راه‌اندازی مجدد API حفظ نمی‌شود. ارسال خروجی از مسیر شبکه فرایند API انجام می‌شود؛ اتصال سوکت به VRF مدیریتی دیگر پیاده‌سازی نشده است. ارسال‌کننده، تغییر وضعیت تونل، تعویض کلید، وضعیت سرویس و رویدادهای بازیابی پایش strongSwan/IPsec را به اعلان VPN تبدیل می‌کند.

آزمایش تحویل واقعی SMTP و وب‌هوک، گردش کار مرورگر، مسیریابی و بازیابی پایگاه داده همچنان نیازمند پذیرش محیطی است؛ تست واحد جای این پذیرش را نمی‌گیرد.
