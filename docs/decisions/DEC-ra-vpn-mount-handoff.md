# D-237: stable RA namespace handoff across mount namespaces

Date: 2026-10-05. Manager implementation decision within the owner's approved independent strongSwan engine; no new agent/daemon capability or shared-host runtime action authorized. Implementation and independent verification remain unfinished.

The existing agent unit uses PrivateTmp, ProtectSystem and ProtectKernelTunables. Its mount namespace does not propagate new namespace bind mounts to other services. The first disposable production fixture placed agent and VPP in the same mount namespace; that success cannot prove the actual unit/VPP/manager handoff. The [upstream systemd execution documentation](https://github.com/systemd/systemd/blob/main/man/systemd.exec.xml) explicitly describes this mount propagation boundary. A pathname created inside the agent's mount namespace may resolve to an ordinary placeholder in the VPP or service manager's mount namespace.

Options considered: relax unit hardening or global mount propagation; expose a persistent holder's numeric PID path; publish stable owned NSFS bindings through a fixed, bounded broker with held namespace descriptors. The first would weaken protections. The second needs additional between-check-and-use PID reuse proof for consumers that open pathnames later. Select the scoped broker: retain existing agent/daemon unit hardening and capability bounds, use a separate fixed manager-side broker, receive held namespace descriptors and complete boot/process/mount identities, and create or remove only the deterministic owned profile bindings and short alias. Arbitrary paths, commands, mount targets, source strings and foreign bindings are refused. Removal verifies exact NSFS inode and root-owned ownership receipt before unmounting; incomplete or ambiguous identity remains tracked and fails closed.

The VPP and service manager mount namespaces must each be verified. Their equality cannot be assumed from a developer fixture. The implementation must either safely publish the owned bindings in both verified namespaces or explicitly reject an unsupported installation during read-only readiness. A fixed broker does not authorize any shared developer-host mount, service or package modification. Development uses exclusively owned disposable parent/child mount namespaces.

Mandatory evidence: reproduce the hidden-path failure with parent VPP/manager and child agent mount namespace; then run real TAP and private engine handoff, packet policy, restart and exact cleanup across that boundary. Include foreign/replaced binding, boot/process/mount race and namespace lifetime negatives. R2 security, R4 topology/ownership and R8 packaging reviewers must independently verify the final source. Full source and unchanged CI gates remain mandatory. This decision is not a completion or acceptance receipt.

Reversal cost is limited to the new RA namespace/broker adapter, its packaging and owned fixtures; existing native site-to-site and generic descriptors remain unchanged.

## Exact-capability implementation correction — 13:29 UTC

The owned cross-mount fixture proved that opening a held target mount namespace FD succeeds with the existing agent bounds, but actual mount Setns fails EPERM with those same bounds even after unsharing CLONE_FS. [Linux man-pages](https://man7.org/linux/man-pages/man2/setns.2.html) requires CAP_SYS_CHROOT as well as CAP_SYS_ADMIN for entering mount namespaces. Opening an FD is not an actual handoff acceptance test. Preserve this negative regression.

Use the fixed broker in a separate manager-side oneshot boundary, with only SYS_ADMIN and SYS_CHROOT capabilities needed for its mount operation. Existing agent and private charon daemon bounds remain unchanged. Authenticate the root-owned request and held namespace descriptors with full recorded identities; no arbitrary paths, shell, source strings or commands. Unshare CLONE_FS before mount Setns in the fixed subprocess. Packaging installs the unit and helper without developer-host activation; production invokes only the bounded authenticated operation. Exact broker-capability private fixtures, partial publication/removal recovery, namespace death/reuse, foreign replacement and independent R2/R4/R8 review are mandatory before completion. This correction stays within the explicitly owner-approved independent engine design and adds no shared-host mutation authorization.

## Authenticated descriptor transport correction — 13:44 UTC

The exact broker SYS_ADMIN/SYS_CHROOT bounds could not reopen the agent's /proc/PID/fd paths because the source agent retains NET_ADMIN/IPC_LOCK capabilities. Preserve that permission-refused regression; do not add SYS_PTRACE. Use fixed root-0600 SOCK_SEQPACKET socket activation and authenticated SCM_RIGHTS transfer of exactly three typed NSFS descriptors instead. A bounded accepted helper verifies SO_PEERCRED, complete source/target identities and receipts, exact source capability/NoNewPrivileges state, independently checks both VPP and manager mount identities, and serializes the instance operation. No descriptor proc-path reopening or arbitrary FD/path/command selection.

The executable private fixture proved this exact-cap transport and actual target Setns in0.537s, including expected procFD refusal and complete owned cleanup. That prerequisite is not a production-engine acceptance receipt. Final packaging/read-only readiness must verify the fixed socket, listener identity, service/helper and bounded activation contract; private full handoff, partial export/remove retries, foreign/race negatives and independent security/topology/packaging review remain required.

A successful proc namespace open can reference the proc symlink rather than an NSFS inode; NS_GET_NSTYPE must identify the expected namespace type, with matching fstat/fstatfs identity. Agent and broker must not compensate with SYS_PTRACE, broader capability bounds, proc-symlink stat identity, or assumed manager/VPP namespace equality.

Select a narrow manager-preopened target provider: a fixed root-controlled unit uses the canonical numeric VPP service PID to obtain manager and VPP namespace descriptors before dropping capabilities. The consumer receives held descriptors and complete boot/process/namespace identities through the authenticated bounded contract. Verify both roles independently and compare fresh snapshots before publication or mutation.
